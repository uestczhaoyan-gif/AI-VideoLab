# Prompt 构造与保存

用途：把用户的短需求转成可以交给文本模型、编码 Agent 或生成工具的任务。以下是基于现有资料整理的候选模板，尚未完成跨模型或新会话验证；案例目录里的实际 Prompt 继续作为执行证据。

## 保留六层输入

| 层 | 写什么 | 从哪里取 |
| --- | --- | --- |
| 用户 Brief | 主题、受众基础、学习／传播目标、深度／公式策略、长度范围、画幅、语言、声音、素材与资源 | 用户原文、少量澄清问答与明确采用的假设 |
| 方法 | 输入输出、先后依赖、关键实现与检查 | 选中方法的 `METHOD.md`／来源笔记 |
| 风格 | 可辨识的视觉和运动特征、自由变化范围 | 选中的风格文档与实际参考；注明来源和版本 |
| 内容设计 | 对象变化、解释因果或剧情、镜头、时间依据 | 本片脚本、事实资料、事件表 |
| 执行条件 | 可用工具／API、项目路径、版本、复用边界、调用与费用限制 | 实际环境与来源清单 |
| 交付与返修 | 源码／Workflow、成片、资产来源、检查、定位到时间点的修改 | 本片输出规格与反馈 |

便宜模型可以按步骤分别处理脚本、设计、实现和检查，每次只提供相关上下文。是否需要更强模型或更多描述由实际错误决定；长 Prompt 本身不保证好视频，也不固定所有作品的配色、镜头与节奏。

## 模板 A：从资料提取制作方法

```text
请分析下面这个视频／项目，输出一份可追溯的制作方法记录。
来源：{准确链接、作者、版本或视频 ID}
已取得材料：{简介／字幕／抽帧时间／完整视频／文档／源码}

按实际读取范围记录：
1. 它要制作什么视频，展示了什么结果？
2. 用户与工具分别提供哪些输入、执行哪些步骤？
3. 按顺序列输入 → 操作 → 输出，以及依赖的模型、工具、参数与文件。
4. 提取公开的完整 Prompt、Workflow、源码和资产获取入口；缺失项明确列出。
5. 说明风格和运动如何实现，哪些建议只适合该案例。
6. 记录人工操作、筛选、失败、费用与版本条件。
7. 对应用途、形式、风格、技术和方法标签。

分别标注作者声明、可核对的实现事实、你的推断和待验证项。
引用视频时间点或具体文档／函数。没有取得的内容留空或标未知，不能根据标题补写正文。
同一作者的视频与项目互相关联，不作为两次独立验证。
输出按 docs/library/templates/SOURCE.md 的结构组织。
```

## 模板 B：为一个主题生成制作 Prompt

```text
你负责把以下需求转成可执行的视频制作任务。

用户 Brief：{原文与已采用的默认值}
目标观众、前置知识与看完应理解／感受到的内容：{目标}
讲解深度与公式策略：{入门／专业概述／推导；核心公式、符号、假设与必要证据}
视频用途／形式／视觉风格：{分别填写；可让助手按内容选配}
候选方法与资料：{只附本次相关文件，注明证据与未验证范围}
素材：{真实截图、图像、数据、角色参考、声音与缺项}
资源与工具：{实际可用引擎、API、硬件、版本}
预算：{币种、总上限、单步尝试上限；未知则说明}
输出：{画幅、时长、帧率、语言、是否配音／字幕、文件形式}

请完成：
1. 确定一条能满足目标的路线，解释依赖、主要成本和不确定项。
2. 设计观众依次看懂什么，写对象当前状态 → 动作／事件 → 结果，或等价的剧情链。
3. 选择旁白、音乐或动作事件作为时基，规划必要的阅读、动作和转场时间。
4. 生成分步骤执行 Prompt：内容／分镜、资产、代码或生成镜头、声音、合成、检查。
5. 每一步写输入文件、具体操作、输出文件、检查和失败回退；缺少实际接口的步骤标为手动或待补。
6. 指定一个代表真正难点的最小预览，然后再安排批量或高质量制作。

从方法中复用机制，为当前主题重新设计内容；精确功能、数据、主体身份和因果不得被包装改写。
将风格固定特征与本片可变的故事、色彩、构图分别说明。
结果必须能保存为 WORKFLOW.md 和 PROMPT.md；当前只生成方案，不把计划写成已经执行。
```

## 模板 C：把任务交给制作模型／编码 Agent

```text
任务：{本步骤的明确目标}
必读输入：{Brief、采用的脚本／时间表、相关方法与风格文件}
允许复用：{基础设施、组件、资产及版本}
本次需要新写：{内容、对象、路径、镜头、代码或工作流}
实际可用工具：{工具与接口，不虚构能力}
输出目录与规格：{具体位置、分辨率、时长、帧率等}
预算与尝试上限：{已确定值}

制作与检查：
- 先把本步最关键的设计变成可检查的样帧或短预览，再完成其余部分。
- 若使用浏览器／逐帧组件路线，画面状态由帧号或时间确定，字体和资产加载完成后再导出。
- 若使用图像／视频生成，保存模型 ID、引用图、完整输入、实际参数与采用片段；计划动作与实际发生时间分别记录。
- 画面、声音与字幕引用同一套采用时间数据；保持不需要修改的已通过产物。
- 检查与问题绑定实际输出版本；未完整观看／试听的内容明确写未验证。

交付：可编辑源码或 Workflow、实际执行输入、资产与依赖来源、可重建命令、输出、检查与费用记录。
遇到失败先定位输入、依赖、设计或实现问题；超过本步上限则保存结果与回退选项。
```

## 模板 D：局部返修

```text
输出版本／文件：{具体文件与版本}
时间点：{开始–结束}
可观察问题：{实际看到／听到什么}
影响：{为什么影响理解或观感}
本轮修改：{对应脚本、资产、运动、镜头、声音或字幕层}
保留：{已通过的内容和文件}
需重新生成／渲染：{受影响的最小范围}
复查：{技术检查、前后接续与正常速度视听}

保存原版本和本轮实际输入。时间变化时重新对齐依赖；只修声音且时基不变时优先只重做声音。
不要以叠加全局禁令代替修复本轮具体问题。
```

## 按路线补充的字段

| 路线 | Prompt 必须说清楚的事情 |
| --- | --- |
| 代码动效／Manim／三维 | 对象、状态、几何关系、时间求值、文字布局、引擎版本和渲染方式 |
| 一笔画／形变 | 观众的辨识顺序、结构如何承接、部件对应、关键中间态、镜头与主体范围 |
| 图像生成 | 各参考图分别控制身份、风格、构图还是场景；哪些内容应保持，哪些局部变化 |
| 视频生成 | 单镜动作、主体数量、起止状态、身份参考、观察方式、实际支持的时长／参数 |
| 声音 | 实际朗读稿、声音资产、发音、段落情绪与长度、真实峰值或语义落点 |
| 真实录屏／数据 | 使用的真实版本与来源、必须展示的事实、允许的标注和裁切 |

## 第二批补充：便宜模型的输入拆分

依据 [V06](../theory/extractions/videos/V06-BV1bqx76wEUM.md)／[P09](../theory/extractions/projects/P09-code-animation-prompts.md) 的详细 Prompt 示例，以及 [V09](../theory/extractions/videos/V09-BV1Gg3E6BEbn.md) 的按需规则观点，后续可以按以下候选做法组织输入；尚未做跨模型验证：

1. 从索引选少量相关条目，分别指定主画风、运动与版式；不把全部库放进一个上下文。
2. 为已确定的镜头补齐对象、位置／几何、时间、变化关系、必要中间态与检查时刻；开放创意任务先做设计，再决定需要多细。
3. 保留真实的导出接口要求。比如 `draw(t)` 或 `?t=` 可定位，不自动等于某个导出器需要的 `window.renderAt(t)` 与 `?export=1`；要求制作模型明确适配。
4. 生成画面与声音分开说明，写清是否配音、音乐、音效。没有要求声音的示例，不描述成全套成片流程。
5. 输入参数出现矛盾时先确认采用值；[V07](../theory/extractions/videos/V07-BV1ALnw6YEM7.md) 中 90／140 秒冲突说明不能直接拼贴不同画面的参数。
6. 在同一模型与任务上小规模对比是否需要某段规则，保留真实输出、调用次数与费用，删去无帮助的约束。

详细规格能减少某些实现决策，但不证明模型自动获得叙事与审美，也不能保证作者少量案例的费用适用于别的主题。

生产任务可按导演、编码、素材与审查分配模型，也可为不同模型／风格选择不同辅助规则；不要求每步换模型。评估某条规则时才固定对应模型做对照，具体见 [ROUTING.md](ROUTING.md)。多模型交接时保存各阶段实际输入、采用的中间文件和已加载 Skill，而非仅存一个总 Prompt。

## 完整输入怎样归档

每次执行前保存实际发送的 Prompt。来源原文、生成器模板、填充后的实际输入、补充反馈与最终代码分别保存；只保留“最终总结”无法还原当时执行条件。

记录准确提供方与模型 ID、日期、工具权限、引用文件版本／哈希、调用次数、费用和实际输出。无法核实时写未知；目录叫 `DeepseekDemo` 或视频标题写某个模型，不足以证明执行身份。

既有记录继续保留原路径：`UPSTREAM_PROMPT.md` 是作者输入快照，`extension/PROMPT.md` 是案例输入，`METHOD.md` 中的复用模板是归纳产物。三者互相回链，不覆盖替换。费用与验证结论仍以实际执行记录为准。

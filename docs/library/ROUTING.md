因此要记录两件事：**哪个模型承担哪个任务**，以及**某个模型在某类风格任务上需要什么辅助**。多 Agent 不等于多模型；`claude -p` 是运行时调用方式，也不单独证明实际后端模型。

## 路由顺序

```text
用途、内容与交付
  → 选择表现形式／技术路线
  → 过滤许可、素材、硬件、接口与预算
  → 为各阶段匹配运行时和模型能力
  → 取当前相关的风格、Skill 与参考
  → 生成并检查中间产物
  → 只对失败步骤升级模型、补资料或换工具
```

不要求每阶段换模型。第一条可用基线可以是一个可调用的主模型加确定性工具；只有质量、耗时或总成本证据支持时，才引入第二个模型。高风险事实和最终审片保留独立检查，但不把“换一家模型”当作正确性保证。

## 按任务分配职责，不先写品牌排名

| 阶段 | 所需能力 | 产物／验收 | 可复用候选 |
| --- | --- | --- | --- |
| 调研与剧本 | 可靠检索、出处追踪、受众与因果表达 | 有出处的稿件；关键事实人工核对 | 现有资料、P10 的逐段批注方法 |
| 导演与拆镜 | 叙事、节奏、对象变化链、完整时间覆盖 | 镜头表、视觉意图、资产需求 | P11 的 SRT 拆分契约 |
| 风格设计 | 参考理解、构图与媒介语法 | 一张代表帧、一个关键变化；不是只改颜色 | P09／lemo 风格参考；P12 motion-design |
| 编码制作 | 对所选引擎、时间线与工具的掌握 | 可编辑源码、可定位日志、低成本预览 | Manim Skill、Remotion Skills、HyperFrames、Anidoodle |
| 图像／视频素材 | 身份、动作、质感与可用生成接口 | 采用片段、原始输入、素材许可 | 当前缺完整实测链，保留为待补路线 |
| 声音与对齐 | TTS、音色一致、时刻对齐、实际试听 | 音频与句／词时间表；实际接口支持相应输入 | 不强制逐字对齐，按表达需要选择 |
| 渲染与合成 | 确定性工具，不依赖 LLM 猜测结果 | 视频、规格与错误码 | 现有渲染器、FFmpeg、各路线原生导出 |
| 审查与返修 | 实际看图／看视频／听音频能力及事实核对 | 带时刻的问题与复查状态 | 自动技术检查 + 独立审查 + 人工采用 |

试听、整片视频理解等能力必须按实际接口确认。没有音频输入或没有真的读取音轨，就不能写“听过了”。渲染器与模型分别选择；浏览器代码、Manim、Blender、生成视频也不共享同一套执行约束。

## 风格适配表应该记录什么

每项记录绑定 `task + style + provider/model_id + runtime/version + skill/revision + reference + renderer/version`，以及输入、尝试次数、实际加载证据、输出、质量、耗时和费用。未知字段留空并说明，不用作者简称替代官方模型 ID。

对同一任务有三种可能：模型本来就能完成；加入一条相关 Skill 有帮助；Skill 与运行时／模型不兼容或产生干扰。现阶段所有新增组合均为**待测**，不预填“擅长”“通过”或推荐分。

制作时保存实际拼接后的输入或其可恢复引用、调用配置与脱敏日志，才能区分“规则效果不好”和“规则根本没被加载”。不给所有模型塞入全部风格库；按任务检索并消除用户级、项目级和 Skill 之间的冲突。

## 用代表难点验证，不逐风格做完整 demo

1. 先利用已有平面、等轴、一笔画、三维和形变案例识别共性与失败。已有输出可作参考，不能冒充新模型的实验结果。
2. 先覆盖几类机制：文字／排版、对象变化与连续性、数据／科学表达、材质／空间、声音／时间对齐。优先选择最影响下一次真实制作的两类，不把列表全部变成开工队列。
3. 对所选难点固定一个短任务，采用约 5–15 秒片段或几张代表帧。连贯性任务保留足够变化和接续；单张静帧不能验证动作。涉及长片的分段恢复，则测时间覆盖与局部修改，不先做长片。
4. 先只比较一个可调用模型的“无该 Skill／有该 Skill”。固定 Brief、参考、引擎、预算与评分口径，记录内部工具调用与重试；能控制随机性时固定它，否则保留采样差异。
5. 只有结果会影响模型选择时，再加入第二个模型。要比较 Skill 增益，两个模型各做自己的 A/B；不要拿“模型 A＋Skill”和“模型 B 裸跑”直接归因。初次结果只作筛选，有价值的差异再重复。
6. 质量检查包含信息准确、风格特征、动作／衔接、可读性和音画同步；费用包含失败、重试、工具与人时。便宜单价不保证便宜成片。预算／重试上限必须在执行前确定。
7. 将结果回写为可用组合和失败回退，再在真实制作时检验覆盖不足之处。无需穷举所有模型 × 所有风格 × 所有 Skill。

## 后续推进与停止条件

- **资料层，已补：** 四条视频全时间范围的两秒字幕采样；P11／P12 核心提取；相关公开仓库快照与获取范围。原声、V07 附件和个别准确出处仍有缺口。
- **组合层，当前草案：** 优先整理“字幕驱动代码动效”“科普／数据解释”“真实素材与代码包装”三个 recipe。每条只引用所需资料，写清输入、可调用后端、时间表、产物、检查和回退；资源不足则不能标为可执行。
- **验证层，尚未启动：** 根据真实任务选择最有价值的短对照；当前不购买 API、不自动装全局 Skill、不新增完整 demo。
- **界面层，后置：** 先让一个已有路线能接收结构化 Brief、产生中间文件并局部重试，再做选择入口。先提供用途、风格、素材、声音和预算，不让用户手动拼内部模型拓扑。

每轮收集应解决一个明确缺口或提供新的可复用构件。信息足以支持当前选择时收尾，不递归追完全部作品集合，不以收藏数量或 demo 数量作为进度。

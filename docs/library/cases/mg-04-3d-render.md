## 目标与交付

1. 原质量复现（不启用 `v5` 变体）。
2. 拆解“材质与运动必须共同设计”的实现。
3. 新概念拓展 RIPPLE「一触，层层回应」：软胶球落软垫、周边阵列连续回应。

## Prompt 结构与规格

- 五段式上游模板（结构说明见 [mg-01](mg-01-flat-vector.md)）。
- 固定输出 1920×1080、24 fps、恰好 10.000 s（240 帧）、−14 LUFS、true peak ≤ −1 dBTP。
- 风格特征：PBR 真实材质、浅景深、柔和棚拍布光、克隆器阵列、软体碰撞、糖果色软胶。
- 技法：SSS + AO + HDRI 三点布光；Cloner + Effector 群体波浪；长尾 ease（前 20% 完成 80% 路程）；24/25 fps 电影帧率 + f/1.8 感。
- 创意种子：MoGraph 式克隆阵列 + 主物体（充气字标或软胶 logo）落下、压扁回弹、碰撞排开阵列；材质三件套（糖果粉／桃色 SSS、奶油／淡紫亮面、磨砂玻璃或铬）；ASMR 落地声、挤压声与撞击帧同步。

## 时间轴与结构（原版）

- 逐个落下的软胶字母先建立材质与重量感。
- 近一万个胶囊构成可响应地面，使接触可见。
- 银色句点成为更强撞击事件，触发阵列飞散、波动与色彩变化。
- 最后回落为稳定品牌构图，最终状态保持足够时间让材质与字标被看清。

## 工程与渲染要点

- **运动先计算再渲染**：`sim.py` 生成逐帧数组与事件表；字母用一维接触动力学（弹性支撑、阻尼、形变），不是通用软体求解器。
- 胶囊位移与发射时间预计算；共同触发源组织大规模运动，避免对象彼此无关地抖动。
- **场景与材质**：`scene.py` 组合字形网格、胶囊阵列、软胶材质、镜面圆球、HDRI 与棚拍灯光；Cycles 负责光照反射。
- “柔软”来自模型 / 材质 / 灯光，不只靠粉色。
- **双阶段画面**：Blender 出三维底片，`index.html` 再加调色、前景景深、颗粒、暗角与文字；原始 PNG 不能直接当最终成片比较。
- **声音读事件**：配乐脚本读接触时间组织落地、挤压与撞击声；起音误差帮助定位同步问题，不代替听感。
- 本机适配：仅用独立 `tools/blender-cpu.py` 把上游 GPU 设备选择切到 CPU，不改模型、材质、灯光、相机与采样。
- 保留 Cycles、原分辨率、24 samples、自适应采样和降噪；首次还需上游 `assets/hdri/`、字母网格、DM Sans 与 Noto Sans SC。
- 低清预览：480×270、4 samples、自适应阈值 0.15 出三维底片，加原网页调色／排版后输出 960×540、24 fps、10 秒；只用于看完整动作，不能作原质量验收。

## 实际结果（原文数字）

- 原作重建（2026-10-17 核验）：240 帧、1920×1080、24 fps、10 秒。
- 母版 31,074,926 字节（约 31.07 MB）、预览 8,475,137 字节（约 8.48 MB）。
- 约 −14.0 LUFS、真峰值约 −1.0 dBFS；9,991 个胶囊的预计算运动。
- 与上游碰撞事件比对：239 个数值叶节点不完全相等，最大绝对差 **3.552713678800501e-15**，均为浮点末位差异；未以“文件不完全相同”误判动画算法错误。
- 原质量任务墙钟约 **9.93 小时**（含剩余 238 帧渲染、配乐重建、网页合成与检查）。
- 先前按 9 秒那帧 73.1 秒线性外推的约 4.9 小时明显低估。
- 低清预览：240 张底片校验通过，960×540、24 fps、10 秒，完整解码 240 帧；三维渲染约 7 分 45 秒、网页合成约 21 秒；约 −14.0 LUFS、−1.0 dBFS。
- RIPPLE v2 最终成片：192 帧、1920×1080、24 fps、8 秒、4,426,887 字节。
- RIPPLE v2 任务 2026-10-18 14:09–16:03，约 1 小时 55 分钟；计划任务返回码 0，192 张帧齐全，无残留 Blender 进程；约 −16.0 LUFS、−2.2 dBFS。

## 用户反馈（原文）

- 低清版：“除了画质以外都还可以。”→ 动作与整体方向获认可，不提前替代原质量验收。
- 原质量版：“很满意。”→ 原版效果验收通过。
- RIPPLE v1：“可能是排布不够紧密，没有那种一层一层一圈一圈的流畅感。”→ 记为迁移失败。
- RIPPLE v2 运动验证：“这次还不错，可以继续下一步了。”；v2 Blender 成片：“好的，继续后续的工作。”→ 记录当前结果可接受并进入下一种风格，不扩展为所有材质细节均获高度认可。

## 失败与未验证边界

- 首次后台启动器只完成第 0 帧就退出，退出原因未留下日志；当时只有第 0 帧与试帧 216 两张原质量帧，状态文件却停在旧的 rendering。
- 结论：**不能把“启动成功”当“持续运行”**；修正为按每张完成帧更新状态（原子替换）、用 Windows 任务计划承载一次性任务，并同时检查任务状态与实际输出。
- 检查脚本曾因 PowerShell 把 JSON 日期自动转成 DateTime 而误判进程启动时间，改为按 UTC 值比较；任务状态 Running ≠ 已有成片，注销、关机、睡眠仍可能中断，已完成帧可续跑，不承诺后台任务必然完成。
- v1 被否定后，旧源码／视频／Prompt 整体归档在 `revisions/v1/`，旧高质量任务停止，不覆盖失败证据。
- **原文自相矛盾**：`revisions/v1/README.md` 仍写“1080p 版本仍在渲染，不作为已完成成果链接”，而案例 EXPERIENCE 已记录 v1 被否定、任务被停止、v2 取代；归档按 EXPERIENCE 记录为准，同时保留该矛盾。
- 低采样预览的降噪与质感不能作画质验收；单张试帧耗时不能线性外推整片耗时；未完成主观审听（RIPPLE 音轨提示高频较少、与默认 −14 LUFS 目标不同）。

## 对 VideoLab 可复用的要点

- **Workflow**：选一个主事件 → 反应分层（主物体压缩回弹、接触区形变、周边延迟响应、整体恢复）→ 先定运动与接触再定材质灯光 → 同一事件表驱动声画（接触重音／传播提示／收束）→ 预览验完整动作顺序与画面边界 → 原分辨率关键帧验软胶／反射／阴影／降噪 → 稳定后才全片高质量渲染；高质量任务必须逐帧输出、可续跑、真实进程检查。
- **Prompt**：迁移的是“一个主物体 + 能响应接触的环境 + 可见材质差异 + 清楚主撞击事件 + 稳定收尾”；不再犯的错误是只换字样。
- v2 修订 brief 示范了如何把用户否定翻译成可执行约束：紧密排列成连续表面、波峰按半径连续外移、相邻单元共享平滑波面、固定底部。
- **质检**：耗时要用开场／高潮／结尾多个代表帧估算；任何“任务已完成”都要同时核对任务状态、进程与逐帧产物；失败版本与修订依据必须保留；运动认可 ≠ 材质画质验收。

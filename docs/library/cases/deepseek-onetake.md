# DeepseekDemo 一笔画引擎与三部片（deepseek-onetake）

> 归档 2026-11-06。依据删除前的 `DeepseekDemo/README.md`、`REBUILD-NOTES.md`、`docs/METHOD.md`、`docs/NEXT.md`、`films/two-points/README.md`、`films/life/README.md` 整理，未重跑。目录名“DeepseekDemo”**不证明实际模型身份**（`PROJECT.md` 已记此边界）；本文件名中的“onetake”指一笔画／一镜到底，不是外部 Onetake 仓库（见 [P16](../../theory/extractions/projects/P16-onetake.md)）。

## 来源与目标

- 复用来源：`demo/mg-styles-15/demos/03-line-art/` 的 `DESIGN.md`、`METHOD.md`、`EXPERIENCE.md` 与上游 Prompt（现按 [mg-03](mg-03-line-art.md) 阅读）。
- 渲染基础设施：上游 `source/harness/render.mjs`、mgaudio、字体与颗粒纹理；快照现按固定版本位于 `resources/mg-styles-15/source/`（见 [resources](../../../resources/README.md)）。
- 上游重建成片**只作参考帧**，用来量最终构图坐标、读节奏、对照检查。
- 目标：检验“项目里已经写下的设计与方法笔记，够不够重写一遍这条片子”——所以只用文档 + 参考帧，**没有打开上游 `demos/02-line-art/film.js`**。
- 重写的是实现：`cues.json` 每一条路径、每个时间点、镜头模型、填金与门洞合成、字标排版、`audio.py` 整段配乐。

## 引擎与数据模型

- `engine/linefilm.js` 是一笔画通用引擎，三部片共用；全部由 `cues.json` 驱动。
- 字段：`pieces`（路径与收笔时刻）、`circle`／`spiral`／`rings`（解析圆、螺线、同心环）、`dots`（点光源）、`logo`（圆面、孔、填金）、`captions`（科普字幕）、`pulse`、`camera`（缩放曲线 + 跟随参数 + 交还构图）、`type`、`pen`、`look`、`music`。
- 做新片只改 `cues.json` + `audio.py`。
- 顺序不能颠倒：先定最终构图 → 再定形体链 → 再写路径 → 最后配声音（先做声音会让人把画面去凑音乐）。

## 时间轴与镜头做法（ATELIER 复原的反推）

- 用 0.5 s 间隔联系表读上游节拍：0.2–0.6 入线卷种子；1.0–1.8 茎与三叶；2.2–2.6 屋檐；3.0–3.4 房子；3.6–4.2 塔；4.4–5.0 穹顶与尖顶；5.2–5.8 基线长跑；6.0–6.6 浪峰绕环；6.8–7.4 山脊回走与圆环；7.4–7.8 线转面；8.0–8.6 反向光脉冲与退镜；8.4–9.4 字标。
- 本次实现与上述节拍对齐到 **±0.2 s**。
- 笔速不按段写死缓动，而是把“每段收笔时刻 ↔ 累计弧长”作锚点做单调三次（Fritsch–Carlson）插值：C1 连续、不过冲、转角减速、长线加速，无分段接缝速度跳变。
- 镜头模型：`cx = 平滑后的笔尖 x + lead(t)/z`，`cy = 平滑后的笔尖 y + leadY/z`。
- 笔尖取 ±0.34 s 加权平均，否则画圆环时镜头会绕圈猛甩。
- `z` 单独一条曲线：开场 2.35 特写树苗、看城退到 0.78、结尾回 1.0；结尾把镜头交还整幅构图。
- 最终构图用参考帧量出（单位像素）：地平线 y≈738；树苗根环 x253–275、y714–742；屋檐上层 y=541、下层 y=551；标志圆心 (958,276)、半径 148、门洞 900–1014；字标“ATELIER LINEA”宽约 690、基线 y≈884。数字只用于最终构图，路径本身重画。

## 声音、字幕与检查

- 声音：和声垫（铺满、很轻）+ 事件音（叶片、塔尖、填金）+ 笔触声（跟绘制包络）。
- 和弦与旋律时间点从 `cues.json` 读，改时间轴声音跟着走；只在“线转面”处给一个清亮金属重音；导出目标 −14 LUFS、真峰值 ≤ −1 dBTP。
- 字幕（ONE LIFE）：严格串行，每句在下一句出现前 0.6 s 淡完（引擎 fade 0.45），脚本校验 `overlaps == []`。
- 字幕（TWO POINTS）：剖面横轴是示意、不标刻度，避免假装定量。
- 检查：`tools/check.py` 解码成片、核对帧数／分辨率／帧率、量响度、抽帧出海报与故事板、压预览，并把结论写进 `out/check.json`，不通过以非零码退出。
- **从页面直接渲染的静帧（`out/stills/`，对稿用）与从成片解码的帧（`out/shots/`，验收用）分开，不混用**。

## 实际踩坑（原文记录，值得复用）

1. SVG 两段 `A` 拼不出整圆：两条弧可能选中不同候选圆心，结果不是圆而是“花瓣”；改用按角度解析采样（`circle: {c, r, a0, dir}`），拱门用两段三次贝塞尔近似。
2. 圆面填金要在离屏画布“挖洞”：直接在主画布 `destination-out` 会把背景和线条一起擦掉。
3. 叶片必须用“叶轴 + 半宽 + 法向偏移”生成两条贝塞尔，眼估控制点会出尖喙。
4. `drawImage` 前 `shadowBlur` 未归零会留填金残影。
5. 镜头不能直接等于笔尖，必须时间窗平滑。
6. 开场路径起点为保住结尾完整构图放在 x=-560，导致结尾线条从画面左边缘进入（参考片停在画面内约 10% 处）——记为已知差异。
7. PowerShell 变量名大小写不敏感，同时写 `$film` 与 `$Film` 会互相覆盖（已改为 `$filmName`／`$filmDir`／`$outPath`）。

## 与参考片的差异（原文结论）

- 结构与观感可复原，**逐像素不可复原**。
- 差异项：路径起点、子路径走法（房子“右墙先下” vs “左墙先下”）、镜头逐帧真实值、拱门是否属连续笔画、配乐（本次新写 D 大调）、字标字距字号、颗粒与调色参数。
- 像素级一致需要上游 `cues.json` 与镜头数据，而文档里没有这些值。

## 用户反馈与未验证边界

- 用户反馈：**未记录**。三部片均标“主观验收仍待观看／等待按正常速度观看验收”。
- ONE LIFE 只有作者自评。成立：开场卷曲、风筝、六级台阶、心结、结尾四步收束。
- ONE LIFE 不成立：山顶与旗像“帐篷 + 一根杆”；坠落没有坠落感（镜头跟着笔尖往下）；裂缝像闪电要靠字幕；花叶与茎在小尺寸下缠绕；11.7 s 风筝只剩半只因跟拍切掉顶部。
- 名称“DeepseekDemo”不证明实际模型身份；不能据此声称某模型完成盲测。
- 依赖上游环境：渲染仍依赖被忽略的 harness 与音频库，仅复制入口脚本无法重建。
- `engine/`、`films/`、`assets/` 随本次删除不再存在，只剩本页的数据结构与做法描述。
- TWO POINTS 的科学分寸：艾里斑是圆孔衍射结果，斑点尺寸 ≈ 1.22 λ/D（乘成像距离）；两点进入瑞利判据内确实合成一团；但信息没有消失，模糊是已知 PSF 与真实分布的卷积，可反解；字幕落在“不是超过光的极限，是把信息读出来”，没有声称无限超分辨。

## 对 VideoLab 可复用的要点

- **Workflow**：先定观众依次看懂什么（每个箭头回答“上一形哪个部位变成下一形哪个部位”）→ 先画最终构图并单独验收 → 用四种可画结构组织路径（叶／花瓣环、板／檐双层、凸起、自交环）→ 段末时刻 + 单调三次插值建时间表 → 平滑跟随镜头 + 一次退镜 + 交还构图 → 三通道描边 + 笔尖光 + 颗粒 → 整片只做一次线转面 → 文字整体淡入 → 声音三件套 → 验收清单。
- **Prompt**：本案例没有上游式长 Prompt，价值在“文档足以重写”的验证方法——只读设计与方法笔记 + 参考帧，重写实现并逐项列出与原片的差异；这正好是 VideoLab“来源可追溯、未知不编造”的正面样本。
- **质检**：任意时刻 `t` 重复渲染一致；解码核帧数与音轨；从成片解码的帧与页面静帧分开；填金脏边、文字裁切、笔尖出画逐项查；最后必须正常速度看一遍——这是唯一能判断“高级感”的验收方式。

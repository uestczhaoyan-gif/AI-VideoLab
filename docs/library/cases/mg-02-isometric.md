## 目标与交付

1. 重建白天版原作：地砖铺开、建筑生长、核心塔启动、数据提示、片尾退镜／字标。
2. 设计与代码拆解。
3. 新概念拓展 SUNGRID「一束阳光，点亮一座小镇」，检验持续空间、先后揭示、状态变化与音画同步能否迁移。

## Prompt 结构与规格

- 沿用五段式上游模板（结构说明见 [mg-01](mg-01-flat-vector.md)）。
- 固定输出 1920×1080、30 fps、恰好 10.000 s（300 帧）、H.264 + 48 kHz 立体声 AAC、−14 LUFS、true peak ≤ −1 dBTP。
- 建议路线 Three.js `OrthographicCamera` + 软阴影 + AO，或 SVG 做等轴面。
- 风格特征：30° 等轴投影、无透视灭点、微缩场景、楼房生长、平行滑轨运镜。
- “真实等轴”建议 35.264° 仰角、45° 方位角；技法写的是 SSR（Scale 纵向 86.6% → Shear/skew ±30° → Rotate ∓30°）、按画面 y 排序 Z 序、2:1 像素斜率。
- 创意种子要求运镜为整组平移（无旋转），前中后景视差速度 1:0.8:0.6。

## 时间轴（拆解自 `cues.json`、`main.js`、`world.js`、`render.js`、`title.js`）

| 时间 | 实现事件 | 设计作用（原文解释） |
| --- | --- | --- |
| 0–2 s | 地块按圈铺开，土壤与道路出现 | 先建立空间坐标，再承载复杂对象 |
| 2–4.6 s | 住宅、风机、轨道和高层错峰生长 | 用先后关系组织密度，避免同时抢注意力 |
| 4.625–6 s | 核心塔分段出现；汽车、列车启动 | 把分散建筑聚焦到一个启动事件 |
| 6–7.75 s | 波纹传播、无人机、三组数据标注 | 从静态模型转为“正在运行的系统” |
| 7.75–10 s | 退镜、底板与立体字标逐字出现，9 s 进终态 | 留出整体辨识与品牌记忆时间 |

- 数据卡是演示性文案，不能作为真实城市性能数据；这是系统意象，不是严谨的城市运行仿真。

## 工程与渲染要点

- Three.js 正交相机沿 `(1,1,1)` 方向观察；“2.5D”是外观描述，底层是真三维几何与光照。
- 地块实例化；建筑墙体与屋顶分开控制，共享时间轴、分别错峰。
- 配置中**屋顶延迟 0.375 秒 = 30 fps 下 11.25 帧**，不能拿 Prompt 里“2–3 帧”的较短描述解释最终代码——这是“代码与 Prompt 不是同一规格”的实例。
- 每输出帧内部 16 次子采样，叠加 AO、轻微 bloom、调色、暗角与颗粒；内部子采样不提高输出帧率，成片仍为 30 fps。
- 镜头位置与缩放由 Hermite 关键帧求值，固定观察方向。
- 主字标解析字体轮廓挤出为三维几何；数据卡用屏幕层标注，两者实现路径不同。
- 声音与画面共用 `cues.json`；120 BPM 提供节奏坐标，但原文提醒不能断言每个事件都在整拍上。
- SUNGRID 复用累计渲染器 `js/render.js`、`anim.js`、Three.js、音色库、字体与 Windows 适配；新写场景、对象、运动、文案、事件表与音乐。
- SUNGRID 子采样降为 8 次，原文明确不声称画质与原版相同。

## 实际结果（原文数字）

- 原作重建（2026-10-14）：1920×1080、30 fps、300 帧、10.00 秒；母版约 76.5 MB、预览约 6.6 MB；重建混音约 −14.1 LUFS／真峰值约 −1.0 dBTP（原片约 −14.1 LUFS／−1.2 dBTP）。
- 渲染与合成约 419.8 秒；逐帧 SSIM 平均 All = **0.964928**，只表示像素结构相近。
- SUNGRID：12 秒、1920×1080、30 fps、360 帧；母版约 11.36 MB、预览约 1.06 MB。
- SUNGRID 渲染与封装约 106.7 秒；AAC 音轨约 −16.0 LUFS、真峰值约 −4.3 dBFS。
- SUNGRID 随机定位重渲 3.5 s／8.5 s 哈希一致、无页面脚本错误；已看每秒抽样 12 格分镜。
- SUNGRID 事件设计：0–3.3 s 建能源岛；3.3 s 可见传输；4.6 s 起电池逐格点亮；6.4 s 释放供能光点；7.6 s 起住宅亮灯；9.3–12 s 收束构图。

## 失败与未验证边界

- 只证明“执行上游代码可在本地重建”，不证明模型能从原 Prompt 独立重建同等作品；未完成主观全片审听。
- 剩余差异：编码／颗粒、字体文件版本、GPU 渲染、色彩元数据，均未声称逐像素复制。
- 一次检查在封装结束前启动，读到尚未写完的 MP4；等渲染进程成功退出后重检才通过——不能把临时未完成文件当成片损坏。
- 默认 16 次子采样计算成本高；SUNGRID 降为 8 次且题材更简单，不能用它的耗时证明性能改进。
- 等轴 Prompt 同时写“30° 等轴”和“2:1 像素斜率”；2:1 约对应 26.565°，是不同构造近似（P02 已记该冲突），推广时需分清。

## 对 VideoLab 可复用的要点

- **Workflow**：一句话定义观众最后应理解的变化 → 列必要对象、状态与因果 → 选一个贯穿空间 → 写事件表（开始／关键变化／结束）→ 纯时间求值（可逐帧还原）→ 文字职责拆分 → 先低采样验构图与运动，稳定后再提阴影与子采样 → 按稳定事件表做声音 → 正常速度观看与审听。
- **文字职责拆分**：场景中的标题可用几何／纹理；必须清晰阅读的信息用投影标注或屏幕层。
- **Prompt**：可迁移骨架是「以【视觉风格】制作【时长】的【概念】动画；观众要理解【状态变化／因果关系】；用【必要对象】在可追踪空间呈现【核心事件】；先保证关系与注意力，再自由设计造型、色彩、镜头与声音；交付源码、事件表、渲染结果与检查，说明复用与新写」。
- **质检**：以最终代码而非 Prompt 解释实现；字体要解析轮廓时补字体并记录校验值；验证实际输出时长，不信配置；素材许可与子采样参数分别记录。

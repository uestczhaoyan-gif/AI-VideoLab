# 后期工程技术文章：暂定结构与证据需求

状态：资料准备，不是研究结论。等阶段性开源复现、重构与迁移实验完成后再展开写作。

第一批资料已归档。接下来串行完成实践，在每个案例目录保存 `EXPERIENCE.md`；文章使用这些实际经验与 `extractions/` 的来源笔记交叉分析，不用候选方法替代实验结果。

## 暂定问题

为什么有些 AI 视频看起来只是会动的页面，有些却具备设计与叙事完成度？强模型的优势、完整制作流程的作用、Prompt 的信息结构分别在哪里？其他模型能在什么条件下缩小差距，或在具体任务中做得更好？

## 文章结构

1. **现象与问题定义**：展示具有代表性的作品及不足，区分用途、视觉风格和技术路线；明确“好看”“讲清楚”“可控”“可重建”的含义。
2. **来源观点与解释假设**：保留观点出处、相同观点的多个来源及不同意见；区分作者经验、公开代码、演示和推测。
3. **制作链与能力分解**：内容研究、脚本、视觉构思、资产、动画、镜头、声音、剪辑、检查和交付。分析哪些决定交给了模型、工具或人。
4. **“一句话生成”的实际边界**：记录完整上下文、隐含规则、引用资料、工具、Agent 宿主、迭代、筛选和人工操作。不要把入口字数当作总输入量。
5. **Prompt 与 Workflow 的构造方法**：从实践中总结目标、视觉关系、状态变化、自由度和检查的表达方式；说明哪些约束有帮助，哪些让结果僵化。
6. **实验与结果**：展示原作、复现、设计拆解、独立新增部分与拓展结果；保留失败和修改成本。区分源码重建、提示词再生成与方法迁移。
7. **适用范围与局限**：模型访问、工具差异、小样本、主观评价、资产版权、未完成观看或听辨、未公开的作者过程、版本变化。
8. **可复用交付**：根据证据给出方法选择建议、完整案例、可执行 Prompt／Workflow 与重建命令。

## 写结论前需要的证据

- 质量比较绑定具体作品、版本与评审条件，不能只对比宣传成片。
- 模型归因需要区分模型与宿主／工具／预算／人工反馈；无法对齐时明确写组合效果。
- 每个“方法有效”的结论链接具体实验；未进入实验的来源观点继续作为候选解释。
- 同作者的视频与仓库、转述文章与原帖分别保留，但不当成互相独立的重复验证。
- 重复观点在提取阶段不删除；写文章时合并论题，并保留完整来源索引。
- 与假设相反的证据、没有改善的方法、失败尝试和时间成本同样进入结果。

## 暂不下结论

“只有 Opus 能一句话生成”“某模型专门为视频训练”“更长 Prompt 必然更好”“通过技术检查等于作品完成”等说法，都需来源和实验支持。文章最终题目、结论和建议由实际证据决定。

## 1. 研究价值

**P03-C01〔作者表述〕**：使用 HTML、SVG、JavaScript 绘制画面，浏览器逐帧截图，以代码合成声音，不调用图像／视频／音乐生成模型。仓库声称把整份 Prompt 给编程 Agent 即可重做，细节会因模型变化。

**P03-C02〔研究者解释〕**：这里的自然语言输入承担了导演、设计、时间编排和部分实现规范的大量工作。“通用 Prompt”描述的是可交给不同 Agent 的输入格式，并不意味着主题、分镜或风格没有被固定。

## 2. 明确的故事与笑点

光标扮演想通过人机验证的 AI：先过快点选被识破，再模拟犹豫、手抖和点错，层层验证后通过，最后通过划掉否定字揭示身份。

核心机制是“能力越强，越容易因不像人类而失败”的反差。光标既是操作对象又是角色，界面状态变化推动剧情，不靠真人形象。

## 3. 技术方法

- **P03-C03**：单个 `render(t)` 时间函数；禁用实时随机数、系统时间、自动 CSS 动画和 `requestAnimationFrame`，确定性哈希驱动变化。
- **P03-C04**：SVG 元素加载时建立，逐帧只修改属性与显隐；图层顺序通过创建顺序明确。
- **P03-C05**：唯一 `timeline.js` 保存事件表，页面导出 `SFX_CUES` 给音频脚本；防止画面和音效各自写死时间。
- **P03-C06**：在浏览器中对 `i/30` 逐帧截图，先等待字体加载；作者指定四页面并行，这是该 Prompt 的执行设定，不能保证适合所有硬件。
- **P03-C07**：定格时把所有运动使用的时间钳住，包括线条抖动；只停主体但纸纹仍动，不是真正冻结。
- **P03-C08**：whoosh、riser 等声音按可闻峰值或结束点对齐，不能把文件开始都当作视觉命中时刻。

## 4. 风格怎样写成可执行约束

作者选择 90 年代朋克杂志拼贴：暖米纸、近黑、朱红为主；粗黑不规则描边、纸纹、胶带、撕纸边、网点、硬投影与漫画爆炸框。

具体手法包括：SVG 湍流／位移滤镜制造 line boil，约每三帧换状态；大字的填充与描边顺序明确；冲击时组合快速到位、衰减震屏、短闪白或缩放、速度／集中线与重击声。指定四种字体分别承担中文海报、毛笔、英文马克笔和窄粗标题用途。

**P03-C09〔作者约束〕**：拒绝霓虹、3D、光滑渐变与企业 UI 等不符合此片的元素。它们是当前风格边界，不是 AI 视频的普遍禁用项。

## 5. 逐段制作安排

| 时间范围 | 叙事任务 | 画面与声音机制 |
| --- | --- | --- |
| 0–3 秒 | 建立验证舞台和角色 | 故障开场、卡片重落、光标落地、勾选与加载 |
| 3.5–7 秒 | 熟悉任务后制造歧义笑点 | 逐格点击，半根交通灯引发犹豫，验证失败 |
| 7.5–14.5 秒 | 机器能力升级 | 网格越来越密、光标分身、批量扫描、群体合并 |
| 15–16.4 秒 | 戏剧性反转 | 因点得太快失败；画面和声音短暂冻结 |
| 16.5–20 秒 | 改变策略 | 模拟手抖、绕圈犹豫和误点；配乐由紧张转松弛 |
| 20.25–23.5 秒 | 升级阻碍与悬念 | 连续钻入验证框、可信度逼近 100%、在 99% 停住后通过 |
| 24–30 秒 | 释放与最后揭示 | 密集跳切庆祝、文字反转、光标回望、收黑 |

这里的时间来自作者 Prompt 的计划表，不是本项目测得的已生成视频事件时间。

## 6. 声音设计与参数

音效全部用合成方法，包含带通噪声呼啸、低频下滑撞击、点击、错误蜂鸣、纸声和数字故障等。作者建议同时刻避免无限叠声，给冲击、过渡与轻提示不同作用。

配乐提供两种选择：只用音效，或加入 120 BPM 的代码音乐。后者按剧情从车库朋克变到紧张段、双倍速、真静音、松弛爵士，再回到高潮。相同节拍网格贯穿视觉与音乐。

参数是本片规格：30 秒、30 fps、900 帧、1920×1080、H.264／yuv420p／AAC 48 kHz。它们体现明确交付合同，不构成最佳时长的理论证明。

## 7. 检查与可疑代理指标

作者要求检查编码规格、指定时间点截图、文字裁切／层遮挡／缺字／滤镜黑块、特定冲击前后不超过一帧的音画误差；有问题则修改并重新渲染。

另有“冲击力”代理指标：缩小画面后的平均帧差至少 6、较长完全静止帧占比不超过 10%、黑红面积至少 12%。

**P03-C10〔研究者分析〕**：这些阈值与本片的强刺激拼贴风相关，不能直接测量叙事、审美或学习效果。增加闪烁可能提高帧差而不改善作品；有意静音／定格反而是该故事笑点。因此指标必须结合情境解释。

## 8. 保留的冲突和边界

- 开头和片尾计划黑场，同时强调事件间持续变化；应把有意黑场和故障区与无意死帧分开统计。
- Prompt 中的署名示例带有“30 秒内制作完成”字样；片长 30 秒不等于实际制作耗时 30 秒。未来执行时必须改为真实署名与耗时表述。
- 作者称不同模型可按 Prompt 制作，但未在这个 commit 提供完整跨模型输入／输出矩阵和失败次数，不能据此判定普适效果。
- 没有公开完整成片源码，因此本项目若试做，验证的是提示词方法再生成，不是已有源码的精确重建。
- 大量具体规则提高可执行性，也固定了故事与风格。推广时需要区分可复用的时间、同步和检查机制，与只属于验证码故事的设计答案。

## 9. 后期可检验问题

保持技术与验收约束、放开剧情与画风，质量是否保持？移除一部分冲击手法后，观看者是否反而更容易理解？不同模型完成同样的详细 Prompt，需要多少人工反馈与尝试？这些是后期实验候选，当前不插入制作队列。

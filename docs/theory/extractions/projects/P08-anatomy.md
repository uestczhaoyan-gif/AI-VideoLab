# P08 · Anatomy：把概念做成可工作的物体

来源：[wheresryan22/anatomy](https://github.com/wheresryan22/anatomy)，commit `bc943e40c59998be5da61f9d39c6a983b1116099`，读取日期 2026-10-15，MIT。已阅读 README 与 SKILL 的核心工作流和质量要求；尚未运行示例或完成全库审计。以下是资料提取，不是调用该 Skill。

## 核心问题与方法

**P08-C01〔作者表述〕**：先找一种真实可识别的物体，让物体的工作方式本身解释概念。例子包括用锁的匹配机制解释缓存键、用单打印头服务多个工位解释共享资源、用量规表达高度或变化。

**P08-C02**：先收集真实数值、明确概念并列部件，再建几何。尺寸、数量、读数和动画由同一模型驱动，避免装饰数值与实际动作脱节。

**P08-C03**：抽象浮板和带标签的方框可能无法形成可辨认机制；只做一块大面板也缺少体积与细节。作者用有用途的零件、连接、支撑、刻度和材质层级建立可读性，不把随机纹理等同于细节。

## 技术组织

- SVG 是核心：等轴相机、实体几何、分面色调、深度绘制次序、框架与实时读数。
- WebGL 用于火焰、流体、焦散或灯光等难以仅用线条表达的部分；效果置于前后 SVG 之间并共享相机。
- 可选 3D 模式将活动部件重新投影、着色和排序，其余内容可保持静态；作者标为 beta，不代表任意复杂场景都已验证。
- 独立 Node 构建脚本生成页面；React 路线区分静态几何与客户端交互。源码和已构建示例页都随仓库提供。

## 质量检查思路

**P08-C04**：几何检查关注穿插、管线间距、连接端点、支撑与前后顺序，包括展开和运动过程，不只检查一个静止姿势。

**P08-C05**：线条端点要落在真实边界或对象上；放大检查关节、弯管、表面纹理和文字窗口。几何正确与视觉可读分别核对。

**P08-C06**：shader 的状态变化通过连续包络与淡化处理，避免颜色突变和边缘硬截断；明暗主题的光效不能简单互换颜色。

**P08-C07**：交互含指针、键盘和减少运动的处理；无 WebGL 时基础 SVG 仍应能说明对象。这说明输出首先是可探索的图解，不能直接等同于固定节奏的讲解视频。

## 适用范围与研究问题

作者明确：项目偏向机器、仪器、工具与家具，不擅长没有可构造机制的概念；复杂零件建模和审查可能很慢。3D 性能和验证仍有限，不能从 README 推断所有例子都能实时流畅运行。

研究者问题：机械隐喻是否忠实保持原概念的因果关系，还是让科学含义迁就外观？高细节何时帮助理解、何时增加认知负担？交互控件怎样转成有时间顺序的视频叙事？只用原工具跑通与模型自行构造新机制，需要分别验证。

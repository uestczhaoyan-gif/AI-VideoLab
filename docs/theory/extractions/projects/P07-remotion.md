# P07 · Remotion：把视频表示为逐帧组件

读取日期：2026-10-14。来源是官方概念与 API 文档；本次不安装最新 Remotion，也不改动既有案例依赖。

## 1. 时间模型

[Core idea](https://www.remotion.dev/docs/idea) 将每帧内容交给 React 组件表达。`useCurrentFrame()` 获取当前帧，配置包含宽高、总帧数和 fps；首帧为 0，末帧是总帧数减一。Composition 结合画面组件与视频配置。

**P07-C01〔来源机制〕**：视频可以表示为随帧号变化的内容，布局和媒体能够进入可编辑代码。工程里明确帧数，有助于对齐声音和检查边界。

## 2. 属性动画与风格

[Animating properties](https://www.remotion.dev/docs/animating-properties) 用插值、缓动和离散更新改变位置、透明度等属性，强调动画应由当前帧驱动，避免实时 CSS transition 导致不一致。

**P07-C02**：输出保持固定帧率时，内部运动仍可以按数帧更新一次，用于特定节奏与风格。缓动或离散采样是实现手段，不是统一的质量方向。

## 3. 组件时间与组合

[Sequence 文档](https://www.remotion.dev/docs/sequence) 说明时间偏移、持续帧数和嵌套关系：子组件看到的帧号可相对片段起点改变。当前页面同时把直接使用 Sequence 描述为旧代码常见写法，并推荐新的交互组件方式。

**P07-C03〔研究者解释〕**：资料版本会改变推荐接口，因此复现固定版本项目时不宜自动套用最新文档。应分别记录旧工程实际实现与新接口建议。

## 4. 对理论研究的意义与缺口

前端布局能力可以成为视频生成的一个基础，但逐帧组件模型只解决画面表示、时间组织和工程控制；它不自动解决叙事、镜头动机、科学真实性或声音品质。

后期可研究：共享时间表是否降低组合错误、组件复用是否造成同质化、逐帧可控性是否减少返工。当前仅阅读三个官方页面，没有制作或评价新的 Remotion 视频，也未核对全部版本迁移细节。

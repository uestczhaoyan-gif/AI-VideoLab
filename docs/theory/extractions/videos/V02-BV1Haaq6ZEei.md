**研究者解释**：这更接近“相同起点、分别优化后的作品比较”，不能直接当作一次性同 Prompt 输出对照。初始条件相同不等于整段制作过程相同；多轮调整也意味着展示不能单独支撑“一句话无需返工”。

## 画面里实际能观察到什么

上下分屏展示两个版本，贯穿同一音轨的歌词／文字动效任务。以下是抽帧观察，不是速度流畅度或音频踩点的测量：

| 范围 | 观察 | 边界 |
| --- | --- | --- |
| 0–10 秒 | 上侧使用键帽、搜索栏、密集字阵等视觉组织；下侧以高对比大字、蓝色块和较少附加形状为主 | 不能只由单帧判断动作质量 |
| 12–22 秒 | 上侧加入字符角色、代码背景、图形爆发与像素字；下侧也使用线框、括号、文件形态和表情符号 | 两边都超出了纯静态文字排版 |
| 24–34 秒 | 上侧角色／字符图形接续出现；下侧有信封、环状文字、排版变换等不同表达 | 参考输入和实际修订未公开，差异不能全归因于模型 |
| 36–42 秒 | 两侧都回到文字与角色／表情组合收尾 | 主观偏好、可读性和主题适配需另评 |

用户原笔记认为较弱模型需要更详细调节；这个样本至少说明两个被比较系统都能产出有设计的 MV，但不足以回答谁普遍更好、谁一次生成更稳定。本文不转录歌曲歌词。

## 后期实验关注点

- 两侧场景、文字、运动和节奏怎样对应同一段音乐。
- 是否用相同素材与参考、相同画幅／帧率和导出方式。
- 动作落点与音频起音是否对齐，快慢对比和阅读空间是否合适。
- 初稿与最终稿相差多少，哪一轮反馈产生关键改善。

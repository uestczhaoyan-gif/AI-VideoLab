## 1. 00:00–01:20：操作链被概括成三件事

**V01-C01〔作者观点〕**：生成视频的基础操作可以拆成准备图像、说明想要的画面、把两者交给画布平台。作者反对把这些操作包装成昂贵而复杂的入门知识。

**V01-C02〔制作结构〕**：画面中需要什么角色、物件或场景，就准备相应图像；将图和动作需求写成提示词；使用能组织这些节点的画布工具生成。

作者关于“十分钟教学”“没有壁垒”的表达属于其入门教学主张，不是对专业叙事、稳定产出、失败率或成本的测量。后半段作者也把影视知识与最终审美判断列为真正差异来源，需一起保留。

## 2. 01:22–03:10：先建立可引用的角色资产

以三个角色／对象构成的短场景为例，作者先准备参考图，在 TapNow 新建图片节点，使用专门生成角色设定图的提示词。

**V01-C03**：给语言模型角色描述或参考，让其整理成四宫格／多视图角色设定输入；该示例以竖版生成角色资产。资产图的 9:16 选择不等于最终视频也必须竖屏。

**V01-C04**：身份图可以包含自定服装、配饰等设计，建立自己的角色版本。需要局部修改时，把已有图重新作为输入，仅要求修改对应细节，而不重写整套角色。

**V01-C05**：作者展示一个移除头部装饰的局部修改例，强调重复操作可由 Skill 或提示词封装。没有展示足够多的失败样本，不能据此认定所有细节编辑都可靠。

作者承诺分享角色设定 Skill，但本次没有获得其可核验的公开文件，不补造该 Skill 内容或下载地址。

## 3. 03:12–04:36：把剧本变成可执行的镜头调度

**V01-C06**：生视频之前需要剧本；创作者至少说明场景、角色在做什么、相机观察角度与画面焦点。示例逐步加入人物前行、视线方向、蛇从哪个方向经过等动作关系。

**V01-C07**：不会写规范分镜时，可以先用自然语言表达镜头意图，再交给提示词写手 Skill 整理。作者展示在 Agent 中调用自己的 Skill，将调度转成适合 Seedance 的输入。

**V01-C08**：项目自己的色调、质感、场景约束等可以进入该 Skill，减少重复描述。但不同作品的输入不必相同，作者明确说示例与自己连续剧使用的提示词存在差别。

**研究者解释**：这里仍然存在人工导演层。工具替代的是格式化、补全和重复组织，创作者要决定人物行为、视线、情绪与镜头关系。

## 4. 04:38–06:20：参考绑定、模型参数和声音约束

**V01-C09〔界面演示〕**：把多个参考节点与提示词连接到视频节点，选择模型和片长等参数。画面出现 Seedance 版本与时长选择，仅记录为作者当时演示环境，不作为当前产品规格建议。

**V01-C10**：逐一把上传图映射到角色名和设定，使提示词中的身份有明确引用。作者把这种“参考图锚定”视为保持角色一致性的关键步骤。

**V01-C11〔必须保留的强断言〕**：作者称做好锚定后角色一致性基本稳定，甚至使用了不会出错的措辞。这没有在视频中通过多次试验、跨镜头统计或失败集证明；后期需检验，不能直接写成工程保证。

**V01-C12**：声音要求随视频输入明确，例如是否有 BGM、环境风声、草丛／动作音效、角色发声与情绪。它们不应留到生成之后才默认猜测。

**V01-C13〔个人偏好〕**：作者的规则中限制纯 90° 侧面构图，并让 Skill 根据剧情推断角色站位。这是其作品／工具经验，不是所有视频应该遵守的构图禁令。

**V01-C14**：作者认为明确站位与调度后，不一定需要额外故事板或导演台。他展示了被整理成分镜、景别、动作时间与约束的较长输入。该例不能证明故事板对复杂叙事普遍无用。

约 06:20 起插入了生成结果展示。本笔记不把一次展示当作首抽成功、稳定性或最少成本的证据。

## 5. 06:48–07:48：人最终负责什么

**V01-C15**：作者强调重复的资产／提示词操作可以封装，最后审核画面、判断镜头接续和确定标准的人仍是创作者。

**V01-C16**：同一工具得到不同结果，差异可能在需求表达与影视理解，而不只在模型名称。其绘画／漫画经验被作者视为可以迁移到视频创作的背景。

本段与开头“低门槛”相互补充：能按按钮生成，与能提出和选择高质量镜头，是不同层次。

## 6. 07:50–09:38：连续剧段落的第二个例子

作者展示带台词的两人对话剧本，将其转成约七个镜头，再经 Skill 转为模型输入。

**V01-C17**：每镜头交代景别、人物朝向、相机的俯／正／侧角度、前景、动作焦点及台词，而不只写“两个角色对话”。

**V01-C18**：从大环境进入人物，利用抬头、转身、视线交汇、停顿、呼吸和细微表情组织情绪。镜头调度中有后拉、摇移或跟随，人物状态与摄像机共同变化。

**V01-C19**：整理后的提示词保留分镜顺序、各镜时间与结束状态；明确人物数量和身份，减少角色复制或增减。可见输入还包含场景光线、背景持续状态与动作限制。

这些约束服务这段特定对话，不应变成所有作品的固定镜头数、停顿长度或光线。生成输出仍需检查实际是否实现，不以计划文本代替结果。

## 7. 09:40–11:20：经验传播与能力边界

**V01-C20**：作者说会分享提示词和 Skill，但提到评论或私信分发；本项目没有向作者发消息，也没有假定这些文件已经公开获取。

**V01-C21**：作者最终将能力差异落在影视理解、准确提出需求与审片标准上。基础工具操作简单，不代表更复杂调度和打戏无需专门知识。

作者对培训课程的否定是个人立场；不应直接转成课程价值、学习成本或行业门槛的客观结论。

## 8. 可保留的方法结构

角色／场景资产 → 明确身份引用 → 人工剧本与镜头意图 → Skill 整理为模型输入 → 画布平台生成 → 人工审片与局部修改。

它与代码动画路线不同：语言模型主要帮助构造输入，画面由图像／视频生成工具产生。平台画布、提示词写手和底层生成模型的贡献应分别记录。

## 9. 仍未得到的证据

实际使用的完整 Skill 文件、全部生成尝试、失败率、总费用与人工时间、跨长段落一致性的量化记录、声音的独立验收。它们在当前公开视频中没有充分披露，不因本次资料提取结束而假装齐备。

后期可检验：多视图与身份绑定各自贡献多少；详细调度是否提高可控性；哪些硬限制有帮助、哪些只是作者偏好；导演经验能通过何种 Prompt 结构显式传递给较弱模型。暂不将这些候选方法加入实践线规范。

## 1. 00:00–01:04：代码动画与生成视频的区别

**V07-C01〔作者表述〕**：以代码描述画面与动画，再借助 Remotion 等工具渲染；不是把整段视频完全交给视频生成模型。使用其标注的 Opus 5.5，作者认为其他模型也可尝试，但效果可能不同。

涨粉数量、二手平台报价与“很简单”是视频案例／作者说法，不是本项目对收益、生产速度或任何模型效果的验证。评论区第三方 API 的安全、成本与官方身份也未核查，不作为推荐服务。

## 2. 01:04–01:38：Prompt 先说明角色与交付

**V07-C02〔作者方法〕**：先给执行者明确职责：导演、设计分镜、安排叙事节奏和写代码；同时给主题、受众与希望观众看完理解的内容。示例为《AI 发展简史》，面向完全不了解 AI 的观众。

屏幕中的交付写的是 HTML 动画预览；不能把“预览可以显示”直接说成已有完整 MP4 渲染工程。提到 Remotion 也不证明最终实现确实使用了对应版本的 React／Remotion 工程。

## 3. 01:38–02:30：内容结构与画面增量

**V07-C03〔作者方法〕**：说明时长、章节与每章要表达的节点，并让画面解释内容，而不是把大段稿件贴到屏幕。用户已有稿件时，保留其中事实与观点，再拆成适合动画的分镜。

“像 PPT”在本视频主要指内容没有被转成视觉过程，不是指所有静态文字、卡片或幻灯片形式都不适用。

**V07-C04〔来源内部冲突〕**：01:50 左右屏幕写约 90 秒，02:08–02:10 的信息图写 140 秒／10 章节，03:00 的屏幕规格仍写 140 秒，而字幕说总时长 90 秒。保留这个冲突，不能把各处数值拼成一份已经一致的执行规格；实际制作前必须确认采用值。

视频中的 AI 历史事件与年份是示例内容，本轮未独立核查，不转成研究事实库。

## 4. 02:30–02:54：可执行风格描述

**V07-C05〔作者方法与画面〕**：尽量说明具体媒介、色彩、线宽、运动和参考图，不只说高级、震撼或科技感。示例采用 Remotion／SVG Path、深色底、金色细线、贝塞尔路径逐渐生长与留白。

这套视觉参数只适合其示例；可以迁移的是把形容词转成可观察特征。原示例也保留了“动效华丽、电影感”等抽象要求，不能说它已把全部风格量化。

**V07-C06〔作者建议〕**：说明不希望出现的内容，例如满屏大段文字和无关特效；从模板选一个适合题材的起点，再根据实际成片调整。限制服务当前题材，不形成全局无限增长的禁用列表。

## 5. 02:54–03:40：视频规格与证据缺口

**V07-C07〔作者方法〕**：写清分辨率、比例、帧率、采用时长，字幕与对应画面同步并留出阅读时间。1920×1080、16:9、30 fps 是这个示例，不是所有用途的固定输出。

结尾展示 HTML 动画片段并提到十五套风格资料，但本轮没有获得准确附件入口、模板全文、可编辑工程、渲染命令、版本、声音工程或生成费用。不能凭“15 个”就认定它与 mg-styles-15 是同一套文件，也不记为已取得的新增 15 套。

## 可归纳的 Prompt 骨架

```text
执行角色／职责
  + 主题、受众、传播目标
  + 内容顺序与每段的视觉解释
  + 具体风格和参考、必要的排除项
  + 输出规格、字幕／声音／导出要求
```

适合补充 [Prompt 构造](../../../library/PROMPTS.md) 中的 Brief 与内容设计层。它是制作输入组织方法，不是独立自动化引擎；分类主要为 M01、M02、M07。

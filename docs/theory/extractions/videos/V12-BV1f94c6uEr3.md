## 2. 01:00–07:00 原理：`render(t)` + 无头浏览器 + ffmpeg

**V12-C03〔作者讲解，数学可自查〕**：视频是连续播放的图片，15 秒 × 30 帧 = 450 张图。模型写一个网页并暴露"给定时间就画出那一刻画面"的函数（Skill 中即 `window.render(t)`）；另有工具在后台开无头浏览器逐帧 1/30 秒截图，再由 ffmpeg 拼成 MP4。

**V12-C04〔作者讲解〕**：硬性要求是**任意跳到某一秒都能直接画出那一帧**，不能依赖上一帧状态。因为渲染脚本为了快会同时开多个浏览器，一个从第 0 秒解起、一个直接从第 10 秒解起——相当于翻页动画书，每一页都必须能单独画出来；弹簧回弹、飞行轨迹都由时间直接算出。
> 与 motion-showreel `SKILL.md` 的"画面只由 t 决定、不用 `Math.random`/`Date.now`/rAF/定时器/CSS 动画、帧间不保存状态"一致（等级 A，见下）。

**V12-C05〔作者表述：可修改性的价值〕**：视频模型生成的是一段成片，改一个字要改提示词、整段重来；代码视频哪个镜头太快、哪个数字不对，**重渲那几秒就行**。

**V12-C06〔作者讲解：技术栈怎样选〕**：每个网页元素背后都是 HTML；网页动画就是让属性随时间变化（宽、高、圆角改一改，按钮先变搜索框再撑成卡片）；"运镜"也是改数字——以某个按钮为中心把整个界面放大三倍，就有推进感。复杂图形用 SVG（虚线偏移做出"一笔画出"）；几千个粒子用 Canvas（清空画布按当前时间重画，粒子聚成文字的做法是先在隐形画布读字形像素当终点）；复古/胶片/电影感用 WebGL 着色器（1080p 约 200 多万像素，逐像素算规则；一般由 Canvas 画好内容，再交给着色器加质感，"内容和质感分开，各层能单独跑、单独改"）；立体感用 Three.js（摆物体、打灯、架摄像机，三角形组成物体，可先在 Blender 建好导入）；手绘感用 p5.brush（口播称自带 11 种笔刷、可做水彩晕染；手绘抖动用固定种子或每隔几帧换种子来"活着")。

**V12-C07〔作者表述：声音同表〕**：声音本质是数字，鼓、贝斯、钢琴、点击声都能由代码算出来，导出音频再与画面合成。因为**画面与声音读同一张时间表**，第 3.2 秒的撞击天然对在同一帧上，比剪辑软件里拖音轨对点更准。有口播时，时间表改由声音决定：先配好口播、量出每句起止秒数，画面按真实时长排；作者称"我们现在的视频"就是 TTS 生成音频后逐个匹配画面，可以由模型自己完成。
> "这条视频本身由 Agent 自动制作"是作者说法；本机只看到成片，未验证其生产链。

**V12-C08〔作者表述：适用面〕**：除炫技短片外，把歌和歌词交给它能测节拍做 MV；真人实景这类代码画不出的画面，可让模型当导演调用视频模型生成素材，再用代码合成字幕、特效和转场。

## 3. 07:00–10:43 技巧：把审美要求变成可检查的具体项

**V12-C09〔作者表述＋画面 t00700〕**：不加约束时模型总用同一套套路，单支很炫、刷多了审美疲劳，"现在已经有观众能一眼认出是哪个模型做的"。画面用同一句需求跑三次，结果分别标为「惊艳／翻车／又是老一套」，并写"它也有发挥不稳定的时候"。

**V12-C10〔作者方法：对标〕**："高级一点、有设计感"这类话模型每次理解都不同，给一个对标更稳——一部电影片头、一支广告、一个设计流派都行（举例：火车窗外四季流转配布达佩斯大饭店风格，一个片名就交代了粉嫩配色与对称构图）。**要说清学什么、不学什么**：学节奏、构图、配色逻辑，不照搬角色、镜头和旋律；说不清风格就把截图或录屏丢给它先分析。

**V12-C11〔作者方法：三种讲法〕**：定对标后让它想三种讲法（一段旅程、一次前后对比、一个东西变成另一个），选一个说明理由——"模型第一个冒出来的想法往往就是这种风格最俗的那一个"。

**V12-C12〔作者方法：节拍与转场〕**：先定音乐速度再让镜头咬拍点（120 BPM = 0.5 秒/拍，15 秒正好 30 拍；换镜头、元素砸下、文字弹出都落拍点，观众不数拍子也觉得卡上）；有起伏、有密有松，具体排布让模型按内容定，人只给情绪走向与高潮位置；用现成曲子先让它分析节拍。**有口播时人说话时配乐和音效必须让开**。转场不能只会弹入弹出，"下一个画面从上一个画面里长出来"（上一镜的圆变成下一镜的太阳，镜头冲进按钮进入下一场景）；镜头要动（2D 也能推拉摇）；同一时刻只让观众看一样东西（容器还在变形时文字别急着进）。

**V12-C13〔作者方法：讲解片最常见的失败〕**：把口播一句一句做成标题卡，再用淡入、背景粒子包一层，"看着在动，其实就是在翻 PPT"。分镜时先想清每段要让观众看懂什么变化，让主角在画面里一直演下去。**简单检查法：把字幕藏起来看一遍，光看画面还能看懂，才算真的在讲**。

**V12-C14〔作者方法：产品片〕**：在项目仓库里打开 Claude 让它先读代码、弄明白功能，再提炼卖点排分镜；必须给真实 logo、产品截图、网址和品牌色，否则编出来的界面一看就假，功能、数字、客户名不给就会编；需要取证的可让它上网调研；演示功能时加光标移动、点击和界面反馈。

**V12-C15〔作者方法：自我质疑与可检查化〕**：可以让它"扮演专业动效设计师，质疑你自己的策略和计划，如果感觉不像专业设计师做的就推翻重来"。但"每一帧都要讲究"这类口号不够，**要给能检查的办法**：模型能看图，但看不了连续播放的视频、也听不到声音，所以要把片子换成它能看懂的图和数字（具体在 Skill 一节）。片子越长越不能一口气做完：先出关键帧、方向对了再做动画、节奏定下来再渲高清。

## 4. 10:43–11:29 开源 Skill：`motion-showreel` 与旧 Skill 的分工

**V12-C16〔作者表述＋画面 t00650〕**：Skill 已发布到 Garden Skills 仓库，画面标题 `motion-showreel`、红色标签「全新·视频创作 Skill」。与旧 Skill `web-video-presentation` 最大区别是**节奏由谁掌控**：旧的把文章改成口播稿、一页一画面、点一下走一步、最后录屏，节奏在人手里；当年这么设计是因为模型排不好连续动画。新的把"每一帧画什么、几秒切镜头、哪一拍响什么声音"全排进一张时间表，**节奏交给 AI**。能做几秒片头、几十秒卡点短片，也能照口播稿做 20 分钟讲解视频。

**V12-C17〔作者表述：Skill 的价值〕**：Opus 5.5 很强但发挥不稳定，Skill 把前面的技巧变成流程里固定的一笔：动手前必须先写 brief，把对标、讲法、记忆点、禁止清单写清楚，**brief 跟片子一起交付，下次换主题改一改就能接着用**；内含 43 种风格（赛博/像素游戏/老电视/软萌 3D/合成波/水墨/瑞士排版/电影片头等），每份风格文件写清材质、配色、字体、怎么动、配什么声音、有哪些坑；流程、规则、风格和"截图渲染/配乐合成/检查验收"脚本都是现成的，模型不必自己摸索管线。
> 43 种风格与固定提交里 `references/styles/` 的 43 个风格文件数量一致（等级 A）；"每份写清哪些内容"本次只核对了 INDEX 目录描述，未逐份读。

**V12-C18〔作者列举的适用场景，作者表述〕**：知识博主已录好口播 → 选白板手绘风格，讲哪个概念主画面画哪个，人像缩到角落、原声和字幕不动；独立开发者 App 上架 → 选浅色界面风格，用真实截图做功能演示短片、横竖版一次出；数学老师讲导数 → 概念形变风格讲"无限逼近"；给小朋友做睡前故事 → 蜡笔绘本风格。

## 5. 11:29–15:17 Skill 的四个机制与流程

**V12-C19〔作者表述＋画面 t00800〕**：Skill 的价值被归纳为画面四块：流程 `SKILL.md`、规则 `craft.md · review.md`、风格 `styles/ · 43 份`、现成脚本 `render.mjs`（截图渲染）/`audio.mjs`（配乐合成）等，配文"截图渲染、配乐合成、检查验收的脚本也是现成的"。

**V12-C20〔作者表述：实时预览〕**：用 AI 做视频最难受的是黑盒——等几小时出来发现效果不对，还要花大力气重调。Skill 设计了实时预览：只要开头说一句"我想边做边看"，就打开一个类似剪辑软件的预览画面，全程能看到制作过程，哪一步不对随时叫停引导。

**V12-C21〔作者表述：流程与三处确认〕**：开工前先把需求问清楚（说过的不会重复问）→ 写 brief → 出风格帧（用真代码渲出开场、记忆点、结尾三帧；没定风格就给三个拉开差距的方向拼成一张图让你挑）→ 逐个镜头制作，**做完一个放出来一个**，哪个镜头不对当场指出 → 配乐混音（有口播先配口播、按真实时长排画面）→ 打开剪辑工作区（画面和声音都是真的，可拖播放头逐帧看，口播/配乐/音效分开调音量，觉得没问题点"导出视频"才合成 MP4）。**全程只在三个地方停下来等你：需求确认、风格帧、导出之前**，其余时间自己干，想随时能看。
> 与 `SKILL.md` 工作流里三处 🛑 停点、默认先预览再导出、`progress.md` 的 `--confirm` 状态同步一致（等级 A）。

**V12-C22〔作者表述＋画面 t00880〕**：最后一步检查不能跳——"模型看不了视频也听不到声音"，所以 Skill 把片子变成它能看懂的图和数字：渲染前先验证"同一秒每次画出来都一样"（确定性），每个镜头截几帧自查；出片后看抽帧拼图和运动报告，自动揪出坏帧和看不清的字；声音看波形和响度，还量"最重那一下之前有没有真的留出那口气"；尺寸、帧率、时长等硬指标由脚本判定，一项不过就不交付；工具支持子 Agent 时，再派一个没参与制作的审片员只看这些图挑毛病——"会多花一些 token，但比一轮直接出片靠谱得多"。
> 与 `references/review.md` 的技术检查表、flash frames、`qa/text.json` 文字框景、`DROPS` 呼吸、独立审片章节逐项对应（等级 A）。画面 t00880 同时标出 7 步流程："01 问清需求 / 02 写 brief / 03 出风格帧 / 04 逐个镜头制作 / 05 配乐和混音 / 06 工作区预览 / 07 导出、检查"，黑框写「交付之前，强制自检」。

**V12-C23〔作者表述：模型分工与效果边界〕**：出片稳靠的主要是 Opus 5.5 的能力，"其他模型暂时还追不上"；但只要把流程和要求说得足够细，它们也能做出接近效果，所以 Skill 的价值在于"不是每个人都用得上 Opus 5.5"。

## 对 VideoLab 的借鉴（3–5 条，区分现在能做 / 需要新能力）

1. **现在就能做：把"三处确认门"写进 workflow 契约。** 需求/Brief、风格帧、导出前三处停，其余阶段可无人值守；每处记录确认依据（谁、何时、基于哪个版本）。现有 catalog 的 recipe 草案与工作台方案导出已能承载，无需新执行器。
2. **现在就能做：Brief 模板 + 逐镜头台账落地。** 把对标（学什么/不学什么）、三种讲法、风格信号、记忆点、禁止清单、规格、声音来源、确认记录做成 `docs/library/templates/` 的可校验模板，并让 shot 表包含"要解释的变化 / 对象起止状态 / 承接对象 / 时间依据"。这直接补上 `PROJECT.md` 待办 1 的字段缺口。
3. **现在就能做：把"质检材料"定义成 recipe 的 QA 合同。** 技术硬指标（ffprobe 尺寸/帧率/时长/帧数/音轨/黑帧/响度/峰值）+ 抽帧拼图 + 文字框景 + 按镜头运动/flash frame 报告 + 音频波形；未执行项显式 `NOT CHECKED`，不得默认通过。仓库已有检查工具，先统一输出格式即可。
4. **现在就能做：第三方 Skill 以固定 commit 引用 + 许可 + 触发描述登记。** `motion-showreel` 的 manifest（name/version/compat/description）与固定提交树是现成的登记样板；注意其 description 就是 Agent 的触发契约，VideoLab 的"选型"应同时记录适用与不适用条件。
5. **需要新能力：实时预览工作区与子 Agent 互检。** 剪辑式预览（逐帧、分轨调音、点导出才合成）与"独立审片员"都需要渲染预览服务、会话状态与多 Agent 编排预算；建议先做脚本质检 + 人工终审，再按真实需求接预览与互检。

# V05 · 用 Agent 做讲解视频：我的 AI 视频制作流程和开源 SOP

## 来源与覆盖

- [原视频](https://www.bilibili.com/video/BV1xGah67E1j/)，作者“一只桌子_table”。发布：2026-09-27 20:00（北京时间）；时长 7:32。
- 提取完成：2026-10-15。读取公开简介、章节表，以及已授权视频缓存约每两秒的 226 个时间点（0–450.05 秒）；识别烧录字幕，核对代表性设计与规则画面。未转写音频，不保证捕捉每个快闪字句。
- 关联项目 [Table-VideoSOP](https://github.com/duoduoler-ops/Table-VideoSOP) 另见 P04。视频与仓库分别提取，仓库更新内容不能反向算作视频已经讲过的内容。

## 1. 00:00–01:00：工具各管一件事

**V05-C01〔作者定位〕**：分享自己实际使用的讲解视频流程，包括工具、设计、动画、声音、封面与经验沉淀。

**V05-C02〔工具分工〕**：FFmpeg 用于代码化剪辑、拼接与音视频处理；作者选择 Remotion 做动画，认为它在自己的案例中比 HyperFrames 更适合动画精修、复杂运镜和景深。

**V05-C03〔作者经验〕**：作者认为 ChatCut 的图形动画与三维摄像机能力有限，主要使用其可视化时间线粗剪配音、出字幕，再手动调整；录屏使用 Recordly。

这些比较来自作者当时的体验，不是跨版本的完整工具评测。能力、付费功能与平台条件需后续单独核查。

## 2. 01:00–02:46：项目规则与设计规则分开

**V05-C04**：AGENTS.md 主要承担任务路由与常见注意点。例如录屏任务读对应经验；动画记录关键动作时间，方便后期音效对点。作者的规则可借鉴或修改。

**V05-C05**：设计规则需要创作者自己建立，因为它决定系列视觉与个性。静态测试比较背景、字体、角色与整体协调，参考图可帮助表达目标。

**V05-C06**：动态测试关注传统动画原则，如预备、惯性、跟随、挤压拉伸和次级动作。示例问题包括方块怎样变成电脑、小球碰撞后对象是否表现出受力关系。

**V05-C07**：可以让 Agent 拆解喜欢的运动参考，再做实际测试；静态和运动都满意后，将采用方案写进 DESIGN.md。

作者将三层分工概括为：SOP 写制作顺序，项目规则告诉 Agent 当前该读什么经验，DESIGN 记录画面与运动的设计。它们不是同一份长 Prompt 的三个别名。

## 3. 02:48–03:06：稿件与配音是正式输入

**V05-C08〔作者经验〕**：文案往往是最耗时的部分。作者对所谓去 AI 味写作 Skill 表达强烈不满，这是其个人使用判断，不能作为所有写作方法无效的证据。

**V05-C09**：配音可以用 AI，但建议自己把稿子读一遍，因为有些语言问题看文字不明显。配音与字幕出来后，才进入依赖正式时间的制作。

## 4. 03:06–04:18：按配音拆段，画面必须有增量

**V05-C10**：制作分段应明确三件事：声音已经说了什么，画面要补充什么，屏幕真正需要留下什么。只把配音变成飞来飞去的大字，作者认为仍然接近 PPT。

**V05-C11**：Agent 标出需要人工审查的部分，并推荐适合生成视频的段落，由人选择；推荐不代表自动采用。

**V05-C12**：Agent 读取作者的经验后准备完整生图／生视频提示词与操作步骤；作者自己在 ChatGPT 的 Chat 界面生图，在 Google Flow 生视频。使用理由包括其个人质量体验和额度／费用考虑，不能推广为所有界面的稳定质量差异。

**V05-C13**：角色 IP 和生成工具是使用者需要调整的部分。作者经验针对 Google Flow；换工具时应读取相应官方资料，不能原样假定输入模式与能力相同。

## 5. 04:18–05:25：分段协作与先设计再重渲

**V05-C14**：作者审过分段表后，Agent 准备各段独立目录与开工提示词，作者按段打开多个对话，同时处理手工生成素材。

**V05-C15**：先交设计图与动画标注供初审，避免直接重做整段造成较大 token 消耗。遇到连续状态转换等难点，先做几秒样片；运镜与节奏经验由项目路由加载。

**V05-C16**：开场虽然也是一个分段，作者通常单独打磨，追求更强吸引力。他描述在 Chat 中先让模型提出方案、反思后再认真看第二版，满意后整理为可交给执行 Agent 的 MD；不满意则提供具体方向。

“先看第二版”是作者启发式，没有证明固定多反思一次总会更好。设计 Agent、执行 Agent 和人工选择的作用应分别记录。

## 6. 05:25–06:00：总装、声音、字幕与封面

**V05-C17**：分段完成后组装，再处理 SFX、BGM 与字幕。此前保存的动作时间戳用于对齐声音，声音电平范围已有经验参考。

**V05-C18**：音乐与音效先让 Agent 提案，作者仍靠听辨决定。作者承认声音方法还在学习，并计划继续更新；没有宣称单靠指标能自动验收听感。

**V05-C19**：字幕由人检查错字与遮挡；封面参考按职责区分，一张控制画风、另一张控制构图，再生成不同平台所需的提示词并手动生图。

这与“一次全自动出片”存在明显差别：采用、审图、审听、字幕和生图操作均有人参与。

## 7. 06:00–06:24：返工转化为经验

**V05-C20**：完成一条后让 Agent 梳理哪些环节返工、哪些事项需要反复提醒、哪些原先没注意到的问题可以优化流程，将经验保存供下一期使用。

本视频强调积累，P04 仓库进一步区分规则没写／写了没执行与可删规则；那部分作为项目来源单独记录，不混作此段原话。

## 8. 06:24–07:08：作者明确的限制

**V05-C21**：以初始配音为时基的流程适合在确定时间线上制作。后期轻微改配音虽可行，但动画、音效、字幕要重新对齐，相关画面还需渲染，比直接在剪辑器里拖动时间线麻烦。

**V05-C22**：频繁来回修改会消耗 token，因此流程不适合反复调整剪辑结构。这是作者自述的主要成本边界。

**V05-C23**：作者正在探索 computer use 操作剪映、达芬奇，但认为完成度、消耗和后台运行仍需测试。其关于 Windows 环境的限制属于当时测试条件；不能写成永久产品事实，也不能将营销展示当成完整生产能力。

## 9. 07:08–07:32：开源资料怎么接入

**V05-C24**：资料已公开；使用者需要选择自己的角色／IP、建立自己的设计风格，并可修改生成和运镜规则。做完新片后继续记录新问题。

## 10. 本来源给出的完整协作图景

人确定内容与风格 → Agent 拆解并准备任务 → 人选择生成段和手工操作生成工具 → 分段对话执行 → 人审设计／关键样片 → 总装与声音字幕 → 人验收 → 经验沉淀。

适合后期讨论的不是“人工多所以无效”，而是哪些人工决定不可省、哪些可以通过更好的输入／状态管理减少负担，以及时间线锁定换来了什么稳定性和修改代价。

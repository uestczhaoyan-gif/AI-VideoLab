## 1. 00:00–03:00：科普代码动画与创作控制

**V08-C01〔作者表述与画面〕**：短知识片适合用图形、数字与关系表达；二维可用 Canvas、Remotion、Manim，三维可用 Blender 等。作者所述上一部 46 分钟长片的代码包含动画引擎和各章关键帧脚本。

“一句话可以七八十分”“容易自查”“迭代便宜”是作者经验；不等于内容、科学机制、图表或审美可以免检。展示片也不是无工具、无参考、单次裸 Prompt 的证据。

## 2. 03:00–06:20：拆参考片与同题试验

**V08-C02〔作者方法〕**：从参考中分解画风、节奏、镜头与转场；先粗抽帧，再对画面变化快或弹幕集中的片段密抽，理解动作如何接续。

**V08-C03〔视频展示〕**：同题尝试手绘白板、扁平 MG、水墨、像素、Blender 与 3b1b 式视觉，并展示多种 Skill 与无 Skill 版本。画面出现 Manim、Remotion、HyperFrames、Anatomy、Onetake、Lemo-Opuscar、Anidoodle。

详细对照条件见作者文章 P10；本轮没有取得全部实验工程和运行记录，不根据示例影片作通用排名。

## 3. 06:20–13:20：短片从需求、参考到自审

**V08-C04〔作者方法〕**：给会写代码的 Agent 一个概念与风格参考，再补声音、字幕和导出；也可以选 Skill 或参考作品，让模型先拆解再制作新主题。画面里展示了参考作品集合和 Anatomy 等工具入口。

**V08-C05〔作者案例〕**：四季短片经历自己制作与审片修订；《刷新》先拆解参考账号，再迁移到行为金融主题。有无旁白版本会影响音乐音量、时间与结尾。

**V08-C06〔费用证据，约 09:20、13:00〕**：画面明确区分“按订阅算”和“API 标价折算”。四季约 30 秒，作者报告 83 次调用、处理约 1,600 万 token，API 折算约 12 美元、订阅估算约 0.3 美元。《刷新》约两分半，视频显示做了三个多小时；博客表格记录约 3 小时 40 分，二者不强行统一成一个精确计时。

这些不是 VideoLab 账单；订阅摊销、API 计价与配音／审片另项费用必须分开。

## 4. 13:20–18:00：长片为什么需要外部工作台

**V08-C07〔作者经验〕**：长稿不能只在一个对话中来回改。Obsidian 文件与画布承载稿件、关键帧、评论、回复和任务，Claudian 连接本地编码 Agent；作者混用模型做代码、审稿、调研、配音与试听，自己作内容和采用决定。

15:30–16:22 的字幕进一步说明：Claude 负责代码、动效、派活和项目管理；Codex 参与资料与审稿，作者把额度作为分工考虑之一；Gemini 参与初稿、配音与试听。具体角色由作者经验与资源决定，不是通用能力排名。29:00–29:20 又把审动效、核事实、听声音分开。

已补存 [P18 Claudian](../projects/P18-claudian.md) 固定快照与 README 初读；作者自制的评论、锁定和画布插件没有因此一并取得。具体模型名按视频与作者文章记载，不当作本项目官方版本或能力核验。可复用的是信息组织与分工，不是必须买齐同样的订阅。

## 5. 17:20–23:40：六个节点、稿件与风格

**V08-C08〔作者画面与方法〕**：明确展示六个节点：立项、剧本冻结、风格冻结、关键静帧、动画初版、成片放行。

写稿包括资料搜集、大纲、批注与取舍；篇幅从长博客压缩为适合视频的稿件。风格需要试镜、反复元素和音乐方向，不能只写一张规范。

**V08-C09〔作者失败记录〕**：试过多种复杂数据图后退回平面表达，Three.js 原型的质感不满意后改 Blender。值得保留的是先试真正难点、再确定工具；并非“Blender 永远优于 Three.js”。

## 6. 23:40–28:40：配音、逐句画面与分段重渲

**V08-C10〔作者方法〕**：配音先比较音色一致性、商用条件与时间戳能力，再按实际旁白时间做关键静帧。人先判断每格是否正确表达稿件，AI 再补具体运动。

**V08-C11〔作者工程经验〕**：修改一处就重渲整章很慢，因此按关键帧拆成小段。局部帧变动只重渲相邻段；旁白长度变化需要重排依赖。最终可分机器渲染再拼接，作者报告两台机器全片导出约六个多小时。

配乐音效仍需要限定来源与许可，跨平台不能默认复用平台内曲库。视频简介列出本片使用的 Lee Rosevere 曲目与 CC BY 4.0 署名。

## 7. 28:40–32:09：问题闭环与总成本

**V08-C12〔作者经验〕**：从稿件到整章动画分阶段审阅，最终全片带声音检查；看板跟踪问题、负责人、采用状态与产出，防止“指出过”却没真正修掉。

**V08-C13〔作者报告〕**：长片视频制作人时约 20 小时，不含前期写博客；Claude 工作约 90 小时，约 290 次指令／批注。处理 token 约 38.9 亿，订阅分摊约 50 美元，API 标价折算约 2,000 美元，更多成本明细另见 P10。

31:20 帧中 token 计数还在滚动，不能把动画中间显示的约 14.2 亿当成最终统计；31:24 已显示 38.9 亿。抽帧核对数据时应确认是否处于动画过程。

**V08-C14〔本次字幕补充〕**：

- 07:46–08:08：代码管位置、结构与动效，适用的生成模型或可商用图库提供人物、照片与质感；不是所有视觉内容都必须手绘成代码。
- 08:20–09:20、12:40–12:54：作者让其他模型参与审片／试听，四季做了四版；《刷新》三个多小时中约一小时用于等待审片超时和返工。独立审查也有成本与失败，不是免费质量保证。
- 19:42–20:52：博客改旁白要取舍表格、公式和链接，满意段落锁定；稿件冻结后只做小调整，否则时间与动效联动。
- 21:24–23:28：先做试镜，优先最难镜头；反复元素形成元素表，配乐方向也应早定，而非全片结束再挑。
- 24:38–25:16：逐字时间戳是可选精度；作者称所用 TTS 不直接提供该信息，可另做语音对齐，上一片仅句级起止也能满足部分动画。
- 27:14–27:48：作者报告 574 个小段、平均不到五秒，关键帧变化只重渲相邻段；这是作者工程经验，未取得对应缓存实现。

## 适合提取到 VideoLab 的内容

- 方法层：短片按主题与参考组合，长片拆成能单独检查和修改的步骤。
- Prompt 层：保存参考拆解、采用的风格／元素、每段说明与明确声音要求。
- 工程层：同一时间表、关键帧驱动、分段依赖与局部重渲。
- 管理层：正文与旁白确认、精确批注、问题跟踪、实际文件版本和最终人工采用。
- 成本层：把模型调用、订阅折算、音频服务、人时和硬件渲染分别记录。

分类：以 M16 为编排框架，结合 M01、M06–M10、M13 等；不是新的单一风格或一键免审片平台。

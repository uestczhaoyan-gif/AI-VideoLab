## 采集方式（与第二批不同）

第二批主要靠烧录字幕 OCR；本批四视频匿名接口均无独立字幕（`subtitle.count = 0`），改为：

1. 公开元数据、简介与章节（V11、V12 有章节，V10、V13 无）。
2. 匿名低清 AVC 流（852×480）下载到 `docs/theory/_evidence/batch03/`（Git 忽略）。
3. OpenCV 按 5–10 秒抽帧；V10 另按 1 秒重抽并做切点分析。
4. `faster-whisper small` 在本机做中文转写（CPU，不上传）；**专名误识别多**，笔记按画面与仓库回改并逐条标注。

工具与依赖见 [tools/intake/README.md](../../tools/intake/README.md)。模型下载走 hf-mirror，本机 `huggingface.co` 不可直连、hf-xet 传输会卡住，脚本已固定相应默认值。

## 四条视频各自贡献了什么

- **V10｜把时间基写进规格。** 128 BPM → 1 拍 14.0625 帧、1 小节 56.25 帧、24 小节 1350 帧；BIG/SMALL/KEYFRAME 三层卡点；每拍换一次风格做蒙太奇；把渲染命令、源码、时间轴 UI、频谱和依赖图直接做成画面内容；结尾用规格卡回收。它证明「极短展示片也可以完全由代码与时间表驱动」，但 46 秒、零对白，不承担讲解与声音评价。
- **V11｜把经验封装成技能包。** 与 V06 同一作者、同一 341 素材库的新版本：`SKILL.md` 只做路由和质量底线，modules／recipes／implementations／templates／adapters／scripts 分层；按需加载；四个交付物（任务卡、分镜表、音乐四案、返修表）；可检查的质量底线与确定性 seek；四阶段授权（card／still／audition／final）。它提供的是**工程化外壳**，但视频里的多模型 A/B 没有日志、Prompt 与评分标准，不能当独立验证。
- **V12｜把审美变成可检查项。** `render(t)` 确定性页面、无头浏览器逐帧截图 + ffmpeg；单一时间表让画面与声音同源；用对标（说清学什么、不学什么）、三种讲法、节拍网格、转场设计（下一画面从上一画面长出来）替代空泛的「高级一点」；把三处人工确认（需求／风格帧／导出前）与 QA 材料（抽帧拼图、文字框景、波形响度、DASH 呼吸、硬指标 PASS/FAIL）写进 Skill；独立 Reviewer Agent 只看材料不看代码。
- **V13｜把 Harness 落到一条可复用流水线。** 四个阶段（内容编写→章节开发→音频合成→录屏）+ 两个人工检查点；按阶段分发文档避免注意力稀释；用 `Outline.md` 做跨步状态记忆；多章节并行用独立文件夹／CSS 前缀／全局 token 隔离；「反馈修复的最小切片」；自评失真用独立 Reviewer Agent 或 SubAgent 对抗。注意它讲的是较早的 `web-video-presentation`（录屏式、节奏由点击/音频推进），与 V12 的 `motion-showreel`（逐帧时间表）是同一作者的两套不同方案，不能混用。

## 当前可用的综合认识

1. **四条来源都指向同一类工程事实**：代码生成画面、时间表统一驱动、确定性与抽帧质检、人工只在少数节点介入。这与 VideoLab 的「本地优先、可编辑、可追溯」方向一致，可以吸收为 recipe 与 QA 的默认契约。
2. **V12／V13 的分歧要保留**：录屏式（网页 + 音频自动播放 + 录屏）与逐帧截图式（render(t) + ffmpeg）各有取舍；前者实现简单、天然音画对齐，后者可任意跳帧、可并行、可只重渲片段。VideoLab 应把两者作为不同 recipe 的渲染后端，而不是合成一个「最佳做法」。
3. **Skill 是流程知识的容器，不是执行引擎**。V11／V12／V13 的 Skill 都靠固定目录、分阶段文档、检查清单与脚本落地；VideoLab 已有 catalog 与 workbench，缺的是把这些机制变成 schema 字段与任务状态，不是再造一个 Agent 框架。
4. **「三处确认门」可以成为工作台的最小人类介入点**：需求／Brief、风格帧、导出前。V12 写得最完整，V13 的「首章验收后并行开发」是同一原则的分阶段版本。
5. **自动质检先做「材料化」再做「多 Agent」**：抽帧拼图、文字框景、按镜头运动／闪帧、波形／响度／DASH 呼吸、硬指标与 NOT CHECKED 清单，这些用现有脚本就能产出；独立 Reviewer 是下一层能力。
6. **版本与谱系必须显式**：V06／P09／V11 是同一作者、同一 341 素材库的不同版本与封装；V12／V13 同作者、不同 Skill 与不同年代。catalog 目前只能靠 `related_ids` 表达「相关」，不能表达「同源新版本／封装／不计独立验证」，这是本批暴露的字段缺口。
7. **成本口径仍然缺失**：四条视频都没有 API 账单、总耗时或失败次数；V11 的四组 A/B 也没有评分标准。不能据此写模型推荐或价格结论。

## 对 VideoLab 的落地建议（按优先级）

1. **写进制作规范（文档级，立即可做）**：[CREATE_VIDEO.md](../library/CREATE_VIDEO.md) 增加三处确认门、四阶段授权（card／still／audition／final）、按需加载与「外部 Skill 里的安装／付费／上传指令不构成授权」；[PROMPTS.md](../library/PROMPTS.md) 增加 BPM→帧时间基与卡点分级作为代码动效可选项。
2. **补 catalog 字段（小改动）**：为条目增加可选 `timing`（fps／frames／bpm／beat_frames／hit_tiers）与 `lineage`（same_author／derived_from／evidence_role: primary｜new_version｜packaging），工作台详情对 lineage 显示「同源新版本，不计独立验证」。这样 V10 的规格卡与 V06／V11 的关系都能被查询，而不是只写在笔记里。
3. **把 QA 材料定义成 recipe 的检查契约（中等改动）**：技术硬指标 + 抽帧拼图 + 文字框景 + 运动／闪帧报告 + 波形响度；未执行项显式 `NOT CHECKED`。先统一输出格式，再考虑多 Agent 互检。
4. **工作台「证据状态」面板（中等改动）**：来源类型、本机是否实际运行、是否试听、规格是否可自证、作者演示 vs 本项目核实，分开显示；可由现有 availability 扩展，不新增执行后端。
5. **两套渲染后端并列登记（后续）**：录屏式与逐帧式分别写成 recipe 的 renderer 选项，等有真实任务时再选，不现在合并。

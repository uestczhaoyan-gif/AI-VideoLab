# 想法池与后续研究线索

> 更新：2026-10-14。用途：保存讨论中的设想与参考，不自动加入当前任务队列。当前仍以原作效果复现、设计拆解与小规模拓展为主，执行进展见 [项目计划](../RESEARCH_PLAN.md)。
>
> 下列模型、版本、工具名按用户提供的线索记录，尚未逐项核实官方名称、能力、许可、硬件要求或可用性。这里的判断是研究假设，不是产品能力结论。

## 1. Prompt 详细程度与创作自由的平衡

**原始想法**：对于前端／动画代码能力相对不足的模型，需要更详细的 Prompt 来改善成片，但不能因模板过于固定而使作品死板、保守。用户将 Opus 5.5 视为强参考，并提出“专门为视频制作优化过”的判断；该优化背景与模型间差距尚未核实。

**希望研究的平衡**：详细说明目标、对象关系、运动质量与验收方式，同时给构思、场景、镜头和风格选择留下空间。要让模型掌握怎样推导设计，而不只是照抄逐镜头清单。

后续可比较：同一主题使用简短 Brief、详细制作原则、完整逐镜头脚本，各自的完成度、返工量与新意如何。先有稳定复现案例，再做小对照；暂不启动模型排名或大规模评测。

状态：保留为贯穿研究的问题；不据此追加新的全局硬规则。

## 2. 项目后期：生成与制作流程本地化

**原始想法**：规划、建模思路、剧本等工作仍可通过与 GPT 等智能模型对话完成；尝试把其余生图、视频生成与制作流程放在本地，并探索自制、自训 Agent。

用户提供的候选：

- ComfyUI：本地工作流组织线索。
- 视频模型：Wan2.2、LTX-2.3、Minimax H3。
- 创作平台：自行搭建，或研究 FastMovieAI 等开源项目。

后续需要分清三个层次：本地运行图像／视频模型、编排本地创作工具、训练或微调 Agent／模型。每层分别确认输入输出、硬件条件和可获得的实现，再决定是否进入项目。

启动条件：已有少量质量可靠的制作方法，能明确哪些步骤值得本地化。此时再核查官方仓库、版本、许可证、显存与速度、质量和成本；不在当前 demo 阶段安装整套平台或训练模型。

状态：后期路线候选。

## 3. 代码动画、动态图形和特定风格工具

下表是检索与实验线索，分组沿用用户构想，不代表已完成技术选型。

| 用途／关注点 | 用户提供的工具或项目名 | 后续要看什么 |
| --- | --- | --- |
| 数学、科学解释 | Manim | 数学对象与机制如何变成可理解的动态过程 |
| 代码生成动态图形 | Remotion、HTML/CSS/JS | 场景组织、时间控制、合成和可编辑性 |
| AI 动画引擎 | 雾象 Fogsight | 从概念输入到动画实现的具体流程与开放程度 |
| 线稿、手绘、风格化动画 | muyang-flot-animation、muyang-flat-animation | 两种拼写均保留，待定位准确仓库并确认是否为同一项目 |
| SVG 动画工具 | Svg Animate | 几何变形、路径动画与输出方式 |
| 数学概念短片 | math-concept-film | 是 Skill、工程还是完整 Workflow，能否复现其成片 |

**一句话输入的候选形式**：

> 动画类型 + 主题概念 + 视觉风格 + 附加要求（配乐、音乐等）。

这是用户入口的草案。内部可以补充素材准备、视觉设计、时间表和检查，不要求用户先写完整导演脚本。

同时保留这些形式关键词：分镜式科普动画、幻灯片式动画、卡片式动画、动态信息图、Kinetic Typography／动态文字动画、Motion Graphics／运动图形。

整理时分别记录“内容目的、叙事形式、视觉风格、技术实现”，避免把工具名等同于风格。幻灯片、卡片和文字动效在合适任务中可以成立，问题是是否符合创作者想要的效果。

状态：资源待定位；遇到对应方向的实际需求时再挑选少量候选复现。

## 4. 手工搭建 ComfyUI 工作流的组合设想

按用户原文保留的组合：

- `Qwen Image2.1` + `MiniMax H3`：制作图片、动画。
- `Qwen-3.8-27`，`IQ4` 量化版：完成代码开发。

这些字符串暂作为检索线索，不纠正为其他产品，也不假定它们已有对应本地权重或 ComfyUI 节点。模型名称、量化格式、实际任务分工及可下载资产，待进入此方向时核查。

后续小实验可以是：用一种图像方法建立角色／场景资产，接一段可控动作，导出剪辑；代码模型单独负责工作流或场景实现。先验证每一段，再判断是否值得连成一条流程。

状态：待核实的组合构想，与第 2 项本地化路线关联。

# 从成片逆向设计：One Dot 如何被写成代码

分析日期：2026-10-14。证据是固定版本的原 Prompt、`cues.json`、画面／配乐源码及原片抽帧；没有作者的完整创作聊天记录。因此可确认“做了什么、怎样实现”，对“为什么选择它”给出有依据的解释，不冒充作者口述。

## 1. 先读出故事，再读函数

原 Prompt 已明确提出“一镜到底的扁平世界”，以及圆点、城市、窗户、人物、通知、图标、品牌的结构。这条故事链不是仅从最终成片猜出来的。实际代码调整了时间与细节，不能把 Prompt 里的每个建议当成最终实现。

## 2. 代码怎样承载设计

**对象身份通过形状、颜色和运动接续保持。** 圆点、太阳、气泡等并非必须是同一个 DOM 节点。`dotAt(t)` 将不同阶段的对象描述为一条主角线索。可复用的关键是感知上的接续，不是强迫所有场景共享一个变量。[源码中的主角追踪](https://github.com/Vincentwei1021/mg-styles-15/blob/49052d80bfaf9fa8412cc9710530e5e95a3b8d8c/demos/01-flat-vector/index.html#L642)

**把动画写成受时间驱动的状态。** `renderAt(t)` 分发到世界、室内、图标与字标四部分；对象状态由 t 计算，渲染器可以随机跳到一帧，不依赖实时播放累积状态。先决定状态变化，再选择 SVG／Canvas 等绘图方式。[渲染入口](https://github.com/Vincentwei1021/mg-styles-15/blob/49052d80bfaf9fa8412cc9710530e5e95a3b8d8c/demos/01-flat-vector/index.html#L695)

**弹性不是所有东西套同一条 ease。** `ballA()` 分段处理自由下落、触地压扁、小跳、蓄力、弧线飞行；飞行速度又影响拉伸与转角。`spring()` 处理过冲和衰减，`kick()` 负责短暂扰动。这使主动作与余波分开可调。[落球实现](https://github.com/Vincentwei1021/mg-styles-15/blob/49052d80bfaf9fa8412cc9710530e5e95a3b8d8c/demos/01-flat-vector/index.html#L409)

**镜头是坐标变换，转场是几何关系。** 世界放在一个组内，镜头用平移与缩放定位；室内映射到窗户坐标。缩放跨数量级时在对数空间插值，接近玻璃时加速，抵达后过冲回稳。目标点、速度与落点共同决定镜头，而非机械增加推拉镜头。[镜头实现](https://github.com/Vincentwei1021/mg-styles-15/blob/49052d80bfaf9fa8412cc9710530e5e95a3b8d8c/demos/01-flat-vector/index.html#L248)

**文字参与几何设计。** 代码用字体测量得到字形宽度及点的位置，把图表柱体接入字母 i；字体缺失会改变这段转换。字体是工程输入，不仅是装饰选择。

**声音描述事件，而非只铺背景音乐。** 画面和音频都读同一个 cues，配乐分段 build／drop／outro，动作配有 pop、whoosh 等音效；音乐在部分视觉重击前短暂降低，再在落点恢复。具体音色和节拍可变，事件对齐的机制可以保留。[音频源码](https://github.com/Vincentwei1021/mg-styles-15/blob/49052d80bfaf9fa8412cc9710530e5e95a3b8d8c/demos/01-flat-vector/audio.py)

## 3. 能逆向到哪一步

可以还原：分镜结构、时间表、对象层级、几何路径、缓动函数、素材依赖、音画映射和输出方式。可以解释并验证某个选择的效果，例如去掉错峰后主次是否混乱、换字体后衔接是否偏移。

仅凭最终代码不能恢复：作者所有被放弃的方案、每轮提示词、人工介入量以及真实心理过程。代码里的 R2 注释可以证明有修订痕迹，不等于完整过程记录。更有价值的产物是有证据的设计模型，而不是编造一段作者思考过程。

## 4. 怎样转换成新的创作

```text
主题与观众想获得的感受
  → 找一个可视化的主角或关系
  → 写出它发生什么变化、变化为何发生
  → 为变化选择场景、构图和转场
  → 转为对象层级、坐标、路径与时间表
  → 画面代码 + 声音事件
  → 渲染、观看，再修改设计或实现
```

花园案例的设计决定：

| 学到的机制 | 新概念中的做法 | 改变与边界 |
| --- | --- | --- |
| 主角贯穿 | 种子落入土壤，茎叶生长，形成主花与花园 | 是因果延续，不要求种子在每帧都可见 |
| 镜头服务主体尺度 | 起初跟随小种子，随后逐渐退开，让生长和花园进入构图 | 没有照搬穿窗场景 |
| 主次与错峰 | 主花先完整展开，周围花朵再依次生长 | 从单个对象建立焦点，再增加密度 |
| 动作质感 | 种子落地压缩，叶片过冲，花瓣依次展开、轻摆 | 重新编写 Canvas 几何与时间函数 |
| 音画共同事件表 | 落地、出芽、叶片和花园的时间供两侧读取 | 新编排，复用合成器而非原片音乐 |
| 收尾来自内容 | 花园先形成，标题再说明“微小的开始，也会盛放” | 这是概念片，不是实际植物生长模拟 |

这种方法还可以转向真实产品操作、机制解释或叙事情节，但对应约束要重新考虑。例如科普中的因果变形必须保持科学含义；产品的界面必须来自真实素材；叙事可以选择剪切而非一镜到底。可迁移的是设计到实现的推导步骤，不是把“圆点贯穿”定为所有视频的规范。

## 5. 方法已实现与尚待验证

原作重建已跑通；新概念采用独立场景代码。当前技术和视觉记录见案例 README。一个新概念只能验证这次迁移，不足以声明通用创作能力。接下来由实际观看反馈判断构思、节奏、声音是否成立，再决定进入下一种风格。

# 本地工作台

这是 VideoLab 的可选 Web 入口；默认 CLI 对话制作及两种入口说明见[根 README](../../README.md)。CLI 可直接制作，不必先启动本服务；当前两种入口尚无项目双向同步。

当前实现浏览、检索、参考图预览、收藏、最多三个条目对比、来源文档、用途候选、制作需求、双档阶段策略、浏览器保存重开，以及 JSON／Markdown 引用型任务包导出。制作方案页同时展示**三处人工确认门**与 **QA 清单**，来源页展示固定版本与谱系（同源新版本／同源封装）。当前不执行制片，不调用模型，没有生成 API；`/api/catalog` 等是本地只读服务，不是后期规划的生成 API。

## 启动

要求 Node.js 22+（本机验证 24.14.0），npm。在仓库根目录：

```sh
npm ci --ignore-scripts
npm run catalog:check
npm run web
```

原 `npm run dev` 是同一服务的兼容命令。

默认 <http://127.0.0.1:4317>，只监听回环地址。端口被占用时不终止其他进程；先设置其他 `PORT` 再启动。PowerShell 例如：

```powershell
$env:PORT = 4318
npm run dev
```

首次启动不需要上游缓存或 API Key。缺缓存可浏览索引，但预览／原文件显示缺失；按 [目录恢复说明](../../catalog/README.md#恢复缓存) 获取固定版本。无需重新导入就能运行随仓库提供的索引。

## 数据与持久化

`server.mjs` 读取经过 Schema 校验的目录，动态检查本机媒体／文档的实际存在状态；同时把 `shared/project.mjs`、`shared/project-validator.mjs` 作为应用模块提供（无构建步骤的 ES module 应用必须显式登记这些路径）。前端采用浏览器原生模块，只依赖 Lucide 图标，不维护第二套上游选择器或另一个 Agent 循环。

### 项目契约 v2（2026-11 增补）

制作方案导出的是共享项目数据，除原有 brief／选型／阶段／费用／验收外，现在包含：

- **`gates`：三处确认门**——需求 / Brief、风格帧 / 样片、导出前。状态为 `pending` / `confirmed` / `waived`；确认必须写依据并记录确认时的项目版本；待确认门会出现在导出的缺口里。
- **`documents`：brief / script / outline / source_notes** 四类文档引用，可为 `null`（显式未提供），路径走统一引用与安全检查。
- **`records.checks`：QA 清单**——技术、内容、视觉、声音、完整观看、用户采用六类；状态显式包含 `not_checked`。`NOT CHECKED` 不算通过：`delivered` 状态会被校验拒绝，直到所有检查为 `passed` 或 `waived`。

这些字段由 `shared/project.schema.json` 定义，`shared/project-validator.mjs` 由 `npm run project:schema` 生成；CLI 或脚本可以用 `confirmGate()` / `updateCheck()` 记录真实结果，工作台只展示契约，不代签。

收藏和方案存在当前浏览器、当前地址的 `localStorage`；换端口／浏览器或清理数据会失去这份副本，重要记录用 JSON 导出。每次保存生成新的方案 ID，不覆盖旧方案。模板或 recipe revision 改变时不静默升级旧方案，可从已存列表导出旧 JSON；重新选型另存新方案。暂不支持从文件导入方案、跨机器同步或服务端项目管理。

任务包含需求、模板／recipe 版本、原始路径、来源网址／笔记、阶段交付、候选策略、许可和缺口，不含完整原文／媒体／源码／密钥。模型与价格未核实，所以两个档位只展示候选原则，费用为未知；用户预算不会被当成预计费用。两档使用同一需求和输出规格。用途候选按人工用途标签与少量明确索引关键词匹配，给出理由，不是语义模型判断或质量保证。

方案可以保存包含商业用途的研究草案，但受限／未知许可显示警告，导出会保留阻塞项；不存在绕过预检的“生成”按钮。

## 安全范围

- 只读 GET／HEAD；无执行、上传、安装、模型或发布端点。
- 只提供明确登记的 Markdown 和图片／视频；文档作为纯文本显示。任意路径、`.env`、Git 配置、上游 HTML／脚本不可读取或执行。
- 文件真实路径限制在仓库内，拒绝逃逸的符号链接；校验路径与媒体扩展名。
- 视频支持 Range 与 HEAD；未知媒体和非法 Range 明确失败。
- 校验 Host／Origin，限制为本机地址；CSP 禁止第三方脚本、frame、object，媒体与请求同源。
- 这不是面向不可信多用户的部署方案，没有认证／资产隔离，不应改成公网监听来托管混合许可资产。

## 验证

```sh
npm test
npm run test:ui
npm run loop:smoke
npm run docs:check
```

`npm test` 24 项：归档、Schema／引用、版本、确定性导入、筛选、方案、项目契约（确认门／文档／QA 交付规则）与只读服务。`npm run test:ui` 用本机 Chrome 跑 17 项浏览器检查：目录加载、MG 筛选、收藏／对比、详情（证据状态／时间规格／谱系）、制作方案契约面板、来源谱系标签、保存刷新重开、双格式导出、版本变化、许可阻塞、缺缓存模拟与 1440／768／390／320 布局。`npm run loop:smoke` 用本地确定性动画跑一次 Brief→渲染→编码→QA 的完整闭环（见 [tools/loop](../../tools/loop/README.md)），需要浏览器与 ffmpeg。

浏览器测试使用已安装的 Edge／Chrome 或 Playwright 的现有 Chromium；可以设置 `VIDEOLAB_BROWSER` 为浏览器可执行文件。不自动下载浏览器。本机媒体不存在时相应像素／播放检查明确记为跳过，仍检查缺失状态。截图与测试报告写入忽略提交的 `.tmp/workbench-verification/`；闭环产物在 `.tmp/loop/`。

测试覆盖检索／空结果、商业授权空集合、收藏／对比、本地图片预览、文档读取、双档规格不变、保存／刷新／重开、双格式导出、许可阻塞、模拟全部缓存缺失、契约面板与谱系展示，以及各宽度基础布局和图片像素。预览是参考图，不是完整观看、试听、审美或商用验收。

文件链接检查不核验外链或标题锚点。`docs/archive/` 中按历史路径保留的链接单独报告，不计为错误。

依赖测试／服务与输入来源的详细进度只在 [PROJECT.md](../../PROJECT.md) 维护。
